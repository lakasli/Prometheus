# 普通对话中的图片理解

用户2026-10-24确认图片理解应实际进入普通对话，撤下独立“图片分析”主导航。Web普通会话的单PNG输入已部署并通过浏览器、远端与真实模型验证；新结果见 [本轮记录](conversation-images-validation.md)，不使用[旧独立分析记录](image-analysis-validation.md)或[视觉接口预检](vision-preflight.md)证明本轮已通过。QQ / 微信媒体、音频、ASR / TTS与完整M4仍未交付。

## 对话入口与处理链路

在已有普通会话的输入区选择一张PNG、查看本地预览、填写本次问题，再明确发送图片消息。单次Run依次执行：

1. 服务端验证会话owner、非草稿测试状态与PNG，冻结当前助手或已发布角色、文本模型及视觉调用所需配置。
2. 固定DeepSeek-flash VisionProvider读取规范化图片，生成不超过8000 UTF-8字节的可追溯描述；最多30秒、单次请求。
3. 将视觉描述作为有来源、无工具授权的user-role资料交给现有Native文本模型，结合当前人格和会话上下文回答。文本模型只看到了描述，不能声称直接看到了原图；助手消息以`basis='vision_description'`标明依据。
4. 用户消息保留图片尺寸、摘要、状态等元数据，回答进入普通会话历史；不向管理API返回原图、原始视觉描述正文或凭据。

整个链路占用同一个普通Run及native lease，两个模型步骤顺序执行，不新增并行任务。取消、失败与服务重启不盲目重放；逻辑状态取消后仍等待当前HTTP future退出才释放占用。视觉步骤失败应明确报告，不能继续给出仿佛已识图的回答。已经发往provider的请求可能已计费，取消不承诺撤销费用。

本轮接入非草稿测试的普通Web会话，包括默认助手和已发布角色。角色草稿测试会话暂禁图片；图片消息不能承载前导控制命令或记忆命令。全局Web附件VisionProvider与角色卡视觉模块偏好分开，接入不会改写或自动启用卡片的vision偏好。缺少有效现有凭据或固定官方provider不可用时，图片入口须明确不可用，不静默更换云服务。

## 格式、来源与出域

- 每次一张PNG，原文件最多1MiB，宽高各不超过2048、总像素不超过2097152；JPEG、GIF、WebP、SVG与APNG均未开放。
- 服务端检查签名、chunk长度 / CRC / 顺序、IEND、尾随内容与动画块，再实际解码为RGBA8并重新编码，保留透明度、剥离文本 / ICC / EXIF等元数据。解码器预算32MiB、规范PNG最多2MiB，CPU校验并发最多一个。
- 原始上传文件不落盘。处理中仍会暂存规范PNG的私有SQLite BLOB，不能把`original_retained:false`解释成从未暂存规范图；视觉完成即清图，任何失败、取消或重启中断也清图。
- 规范PNG发给固定DeepSeek-flash，视觉步骤使用服务端固定的客观描述请求；本次问题与产生的描述再交给本Run冻结的Native文本模型。界面应说明这两个步骤，不能把描述路径冒充文本模型原生接收图片。
- 浏览器预览只使用本地blob URL，换图、移除、成功提交、登录失效和离页时回收，不写浏览器持久存储。宿主不根据用户提交的外部图片URL下载文件。

描述关联`source_run_id / source_message_id`，仅对本owner、本会话且高于遗忘过滤水位的历史有效。图片Run不进入自动摘要或记忆候选抽取，避免把派生识图内容冒充用户明确事实。成功描述作为会话来源保留，不套用旧独立工作台的24小时结果策略；更正 / 遗忘在同一事务中清除受影响的描述及旧上下文，并拒绝迟到结果。原始聊天消息、已发送回答、SQLite WAL及离线备份按各自策略保留，不声称所有副本被物理擦除。

实际保留在近期上下文的视觉来源会冻结到本Run的使用记录，普通文字追问使用该来源时同样标注`vision_description`；仅正文中的标记不能建立可信出处。借用视觉来源的回答不进入自动摘要；纯文本追问的真实用户正文仍可单独选择为候选来源。规范PNG临时BLOB全局最多20张，超过上限拒绝新入队，约束在8GB主机上的暂存规模。

## 本轮管理API契约

路径均在认证、owner授权、Origin / CSRF保护的`/api/admin/v1`内：

| 路径 | 行为 |
| --- | --- |
| `GET /conversation-images/capabilities` | 当前Web图片入口的provider / model、`vision_description`依据、格式及资源限制 |
| `POST /conversations/{id}/image-messages` | `{content,client_message_id,image_base64}`；提交本会话的单PNG消息，返回202 `{run_id,conversation_id}` |
| 现有会话消息与Run查询 / 取消接口 | 查看问题、图片元数据、带来源的Native回复，或取消当前Run；不返回原图和视觉描述正文 |

每次发送使用稳定的`client_message_id`核对任务状态。提交结果未知时先刷新会话 / Run，不自动换ID重发。草稿测试会话返回403，图片控制命令返回400；更细字段校验和幂等冲突以本轮实际API与验证为准。

## 已发布的独立诊断接口

旧`/image-analysis`与`/image-analysis/jobs`接口保留其历史兼容边界，不再占用产品主导航；旧任务结果不会自动写回普通聊天。本次新对话链路通过专门的会话图片接口关联Run，不能用任意诊断任务结果替换会话来源。

旧独立任务仍按owner隔离：成功问题 / 结果最多24小时，终态清活跃图片，失败 / 取消 / 中断清问题与结果；到期或显式DELETE逻辑清正文。请求UUID与规范像素 / 问题维持幂等，保留最多1000条无正文元数据，不暗中删除旧ID。旧实际任务要求reader6及`standalone_image_analysis`能力；新会话图片在首次实际使用时要求reader8及`conversation_images`能力，失效的来源元数据也维持该要求；空表初始化不抬高门禁。两者均不承诺清除WAL和离线备份。

本轮验收应覆盖普通对话中的图片实质影响回答、同一人格与会话上下文、来源提示、跨owner拒绝、视觉失败、取消 / 重启、规范图清理、遗忘后描述不复活、浏览器入口与导航。模拟provider与真实DeepSeek记录分别报告；未执行项保持待验证。
