# 微信 iLink 私聊接入

日期：2026-10-24，Asia/Shanghai。本切片实现 Rust 协议适配、单账号持久状态、扫码管理与文本收发。当前验证范围见 [微信验收记录](weixin-validation.md)；本地模拟服务与单元测试不代表真实微信账号已联调。

## 范围与协议来源

仅接入一个微信账号，接收扫码绑定的本人私聊文本。服务端同时核对收件机器人和绑定用户，其他用户、群聊、媒体、未完成消息与格式错误分别隔离，不进入模型。没有群聊、图片、语音、附件或主动群发能力，也不建立 Web / QQ / 微信之间的用户身份绑定。

独立 Rust 实现参考腾讯 [openclaw-weixin 固定源码版本](https://github.com/Tencent/openclaw-weixin/tree/874637a0dbc24050f72d1385add4fc6170a2d726)，版本标记为 2.4.10，完整 commit 为 `874637a0dbc24050f72d1385add4fc6170a2d726`。重点参考 `src/api/api.ts`、`src/api/types.ts`、`src/auth/login-qr.ts` 的客户端协议行为，不引入该项目运行内核，不将客户端描述当作完整服务端契约。平台账号资格、实际登录状态和手机端可见回复仍须逐项实测。

## 管理入口与登录状态

通过现有 SSH 隧道或受保护的同源 HTTPS 入口登录管理控制台，在“微信”页面开始扫码。没有桌面环境、前端开发服务器或手工粘贴 bot token 的要求。

1. 服务端按当前账号版本创建一个最长五分钟的登录任务；无账号时版本为 `0`。全局最多一个活跃扫码任务。
2. 任务所属管理员读取单任务接口后获得 `display_content` 对应的 `qr_content`；前端在本地编码二维码，不抓取任意图片地址。普通微信状态接口不返回二维码。
3. 等待扫码、已扫码、需数字核验与正在核验分别显示。验证码须为 1—16 位数字；没有验证码时停止核验轮询，提交后只用一次，发出请求前清除私有数据库中的验证码。
4. 过期不自动换码，终态、取消、服务中断和重启清除 QR 标识、显示内容、验证码与跳转节点。重新扫码由管理员明确发起；最多保留 32 条终态任务元数据。

状态含义：

| 状态 | 含义 |
| --- | --- |
| `creating / waiting / scanned` | 正在申请二维码、等待扫码或等待手机确认 |
| `need_verification / verifying` | 等待输入数字或单次核验已发出 |
| `redirecting` | 切换经验证的官方节点；最多三次 |
| `verification_blocked` | 核验受限的终态；稍后手动重新扫码 |
| `confirmed` | 新凭据已保存，不等于接收连接已通过 |
| `existing_credentials` | 服务端返回的账号与本地账号、版本和可用凭据匹配；未获得新的 token |
| `expired / cancelled / interrupted / failed` | 已过期、已取消、服务中断或失败；不得继续使用旧二维码 |

`existing_credentials` 缺少明确匹配的账号、缺少可用凭据，或本地已知为 `needs_login` 时必须失败。新凭据采用新 UUID 引用写入私有 secret store；文件使用 `create_new`，Linux 权限为 `0600`，不覆盖旧文件。任务活跃状态、有效期、任务修订和预期账号版本再次核对后，凭据元数据、账号与登录结果同事务提交。失败可能留下私有孤儿文件，不据不确定的提交结果删除可能仍在使用的凭据。

扫码确认后账号先为 `connecting`。只有接收器取得有效 `ret=0` 并提交对应批次才记录 `connected`；单纯启动轮询、HTTP 建连或登录凭据保存都不能代替这一结果。连接检查通过、平台接受发送和手机实际显示是不同证据。

## 收取、游标与回复

接收器每次固定账号修订、凭据 generation 与旧游标。批次中的 Inbox 去重、来源会话、Run、私有回复上下文和新游标一起提交；队列满、入队失败、代次变化或事务失败均不推进游标。错误消息仅记录受限原因与引用，不能把 NUL 等格式错误当成合法文本而永久阻塞同批好消息。没有返回的新游标或空游标保留旧值。

来源身份为 `weixin:<account_id>:c2c:<peer>`。原生模型对话与 `/memory` 命令复用现有有界 Run 队列；长期记忆权限和会话摘要仍由真实来源域计算。普通会话冻结已发布角色版本；记忆控制命令不依赖模型密钥或有效角色模型偏好。本切片不承诺微信角色切换命令。

每个入站 Run 绑定自己的 `context_token` 引用，不把 token 放进模型输入、Run 配置、普通管理 DTO 或导出。发送前重新检查账号、收件人、generation、凭据、上下文与发送期限，不能用下一条消息的上下文替代旧回复。

回复状态包括 `queued / sending / accepted / failed / unknown / cancelled`。`accepted` 仅表示平台显式接受，不证明手机已显示；超时、连接中断、在途取消、无效响应或服务端不确定错误记录 `unknown`，没有自动重发路径。重启将遗留 `sending` 标记为 `unknown`。迟到的明确接受结果可补记原 attempt 的证据，不另发请求。

停用、凭据失效或账号替换会更换 generation，取消旧的排队任务和未发送回复；已在途发送按未知结果处理。停用不删除历史消息、记忆、数据库或旧发布制品。记忆纠正 / 遗忘同时取消受影响会话尚未发送的微信回复，但不能收回已发出或已被平台接受的内容。

## 管理 API 与凭据边界

以下路径均在 `/api/admin/v1` 下，沿用管理员认证、同源 Host / Origin、CSRF 与 `no-store` 响应策略。单任务读取与操作还校验任务所有者。写入携带 `If-Match`；账号修订和登录任务修订分开使用，首次账号版本 `0` 不能被客户端省略。冲突代码为 `weixin_revision_conflict`。

| 路径 | 行为 |
| --- | --- |
| `GET /weixin` | 账号、当前任务摘要、连接检查、投递计数与明确能力范围 |
| `POST /weixin/login` | 创建单一扫码任务，返回 `202` |
| `GET /weixin/login/{id}` | 任务所属管理员读取状态及有效期内的显示二维码 |
| `POST /weixin/login/{id}/verification` | 提交一次数字核验，不回传验证码 |
| `DELETE /weixin/login/{id}` | 取消活跃任务并清除私有扫码内容 |
| `POST /weixin/enabled` | 版本受控启停与 generation 切换 |
| `POST /weixin/check` | 创建单一待检查请求，由既有接收器下一次轮询完成 |

连接检查不会另建并发 `getupdates` 调用。检查绑定账号、generation 与修订，45 秒未完成则失败；代次变化、停用或明确错误不能被旧轮询迟到结果覆盖。token 失效记录 `needs_login` 并要求重新扫码，不能通过停用再启用绕过。

接口不回传 bot token、凭据引用、私有游标、绑定用户 ID 或回复上下文。通用凭据删除入口还检查微信账号和待发送引用，停用不等于可以删除其仍被引用的密钥。二维码和验证码只在当前管理页面内存中使用，不写浏览器持久存储、前端配置或导出。

## 资源与网络限制

这些是 DSH 的初始本地策略，不冒充平台配额：

| 项目 | 上限 / 行为 |
| --- | --- |
| 账号与受管任务 | 一个账号；一个扫码 loop、接收器和发送器，不按历史会话建进程 |
| 原生模型 | 复用全局最多两个活跃 Run；每会话串行 |
| 入站批次 / 响应 | 最多 100 项、1 MiB 响应正文 |
| 入站文本 | 应用最终门禁 16,000 字节；超限隔离 |
| 出站文本 | 4 KiB；超限保留原 Run 回复，发送明确的缩小问题提示并记录原因 |
| 活跃私有上下文 | 最多 1,000 条；上下文最多保留 15 分钟并按引用回收 |
| 回复期限 | 接收后五分钟；到期不擅自换上下文重发 |
| 请求超时 | 普通请求 15 秒，长轮询最多 35 秒，均支持取消 |
| 错误退避 | 接收端有界退避至最多 60 秒；不据此重发未知发送 |

生产协议只允许经验证的 `weixin.qq.com` HTTPS 官方来源，禁止自动 HTTP 跳转、私网 DNS 结果、URL 用户信息、任意路径与查询注入。数值 loopback 测试例外仅在 `cfg(test)` 客户端中存在，不提供生产环境变量绕过。

## 部署与 reader 4

继续执行 [开发与远端部署流程](development-workflow.md)：本地必要检查、提交推送、固定完整 SHA、构建与部署、远端测试，再记录结果。

仅建立空表、无账号扫码任务或检查元数据不主动抬升全局 reader 要求。实际持久化微信账号、已接收事件或出站语义后写入 `dsh_schema_migrations` 版本 `4`。禁用、发送完成或清理临时 token 不降低该版本。发布能力清单同时要求 `weixin_ilink=1`、`weixin_private_context=1`，部署与回滚门禁拒绝不理解这些数据语义的旧版本。

代码回滚不等于数据库恢复，不能删除表、降级标记或重建用户数据来绕过门禁。部署前的 SQLite 一致性备份、上一个兼容制品、配置版本与恢复路径分别记录。树莓派目标仍是 Pi 5 / 8GB / Lite 64 位，本轮现有 Ubuntu 验证例外不等于 Lite 验收。
