# 普通对话上下文预算

本切片用于 Native 普通文字对话与文字 Skill 的请求组装，不把图片生成、独立后台整理或未来 Harness 的原有限额宣称为已统一迁移。短期状态与失效见 [会话状态](conversation-state.md)，实际发布结果另记。

## 完整块与选择顺序

每轮先冻结真实身份和允许来源。系统策略、完整当前输入、当前明确更正、必要的原问题 / 投递证据是必选块。唯一有效焦点续接时读取有权访问的完整原问题，不以 512/1024 字节展示摘录替代执行证据；有歧义时提供候选并要求区分。

近期历史与对应投递状态组成不可拆分组，只把实际确认受理的文字作为历史回复。焦点、约定、摘要、人物、记忆、日记与风格例子按优先级选择。日 / 周 / 月记和兼容显式记忆按原事件覆盖去重，不删除原事实。性格核心保留；风格示例只按已验证的结构化完整组选择，旧原始 Prompt 无可靠分层证明时整体保留，不能从任意字符串标题猜边界。

所有候选有总数和字节上限；最终选择保持完整 UTF-8、JSON、原问题和完整示例组。必要块不能容纳时，先提交拒绝快照，再以明确错误结束，零 provider 请求。可选资料被裁掉后不登记 memory / diary / person / focus / commitment usage。

## 模型窗口与估计

策略按模型标识版本化，管理员声明的窗口还须绑定当前模型服务地址摘要。同名模型换服务后不能沿用旧声明；管理页要求重新核对并保存。没有声明时窗口状态为 unknown；声明也不等于 provider 能力探测或厂商验证。

默认完整请求体上限为 96,000 字节，输入规划上限为 96,000 个估计单位；另预留响应 4,096、协议 1,024、安全余量 4,096。普通文字实际 `max_tokens=1024`，文字 Skill 为 4096。响应预留小于实际请求值时直接拒绝，不悄悄更改请求或吞掉输入。管理员声明窗口时，有效输入上限取“声明窗口减全部预留”与宿主输入规划限额的较小值。

`utf8_serialized_bytes_v1` 计算完整 `model/messages/stream/max_tokens` JSON 请求体的 UTF-8 字节数作为规划估计，明确 `token_counts_exact=false`。它不是 tokenizer、计费数字、provider 上限证明或精确 token 上界。独立 provider usage 与宿主估计分开；没有真实 usage 不补造计费结果。宿主 96,000 字节和 4,096 响应硬上限不因声明大窗口而提高。

## 召回状态与呈现去重

查询可结合当前输入与同来源唯一有效焦点，扩展和候选数均有界。RecallDecision 区分 found、not_found、unavailable、ambiguous、conflicting、expired、incomplete。近期回退不冒充词面命中；未命中不证明从未发生。检索故障且授权账本独立可核验时保留可验证历史并注明 unavailable；授权或删除水位不可核验时明确拒绝请求，不能回退为全库读取或假装遗忘。

冲突检测只比较有来源、同人物、同陈述日期的年龄，以及同历法 / 精度的生日受控字段；不同爱好、不同陈述日期、补充备注或不同历法不自动算互斥，不声称完成任意自然语言矛盾判定。

近期冷却是保守试验策略：仅简短确认 / 自然收尾的自动近期回退，且短资料在同 revision、最近四个完成轮次的实际投递回复中逐字出现，才标记 recently_presented。只进过 Prompt、发送 unknown、来源换版不构成该证据；新的实质问题、明确回忆或词面命中可再次使用。冷却不改变事实、来源权限、好感或联系许可。

## 接口、冻结与回退

- `GET /api/admin/v1/context-policy` 返回当前模型策略、服务绑定状态与 unknown / 声明依据。
- `PUT` 同路径使用真实管理员、Origin / CSRF 及精确 `If-Match`；缺少版本为 428，冲突为 409，非法字段为 422。该保存不修改 RuntimeConfig revision、性格或密钥。
- `GET /api/admin/v1/runs/{id}/context-selection` 在原管理作用域内只读返回块的选择 / 丢弃理由、引用版本、epoch、字节与估计；不返回另一管理员私有 Web 会话的内容，不生成旧 Run 的新证明。

预算快照与 Prompt 同事务冻结；旧请求按自己的策略、来源和消息摘要核验，不因管理员保存新策略改写在途 Prompt。来源撤销、遗忘、约定换版与 TTL 仍可阻止新的请求或发布；物理 lease 直到原传输结束才归还。

已经排队的结果在真正领取发送时再次核验实际持有的新派生快照；缺少原始身份绑定、上下文或 Prompt 时不重建证明。无效项只停止尚未领取的投递，不修改已发送、发送中或 unknown 的真实结果，也不把资料换版伪装成用户更正。

release reader 为 `context_budget=1`。保存过策略、拒绝 / 接受快照后均不能降到忽略这些约束的旧版。仅初始化空表时不虚构已经使用新语义；数据库回退与生产数据恢复继续分别处理。
