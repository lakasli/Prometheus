# 人物关系系统实现契约

本契约对应 `architecture.md` 第 9.2–9.4、9.8–9.9 节的人物来源、身份与字段权限。部署 SHA、真实模型和浏览器结果以本轮独立验收记录为准；本文不代替验收。

## 人物与字段

- 人物使用独立 UUID 和稳定实例身份；相同姓名或昵称不会自动合并。默认私有来源由服务端查询所选真实会话的 owner，客户端不能提交任意 owner。
- 每个字段断言、关系边分别保存可见域、来源 owner、来源类型 / ID / revision、陈述类型、理由和状态。支持姓名、昵称、年龄、生日、职业、性格、爱好、偏好和约定。
- 年龄必须带陈述日期；生日明确公历 / 农历与年、月日、完整日期精度，不根据年龄推算出生日期，不自动换算历法。未知资料不写入空值冒充事实。
- 本人陈述、第三方陈述、推断与人工确认保持标签。人工审核推断后仍保留“推断”标签，不将其重命名为事实。字段有效期到期后不进入模型上下文。
- 新增字段与有向关系均为待审候选。已审核字段冲突返回 `profile_conflict`，审核者必须明确指定要替代的同人物同字段断言。关系不自动生成反向边。

## 身份、跨账号映射及上下文

渠道绑定要求已存在的真实会话、同一私有 owner 和人工核验依据。群 / 频道来源不能绑定为个人账号身份。

同一来源域的档案可明确合并或拆回。合并保留原字段、边端点、身份和好感事件，不通过累加分数提高好感；拆回恢复原归属。带跨账号身份组的档案须先解除组映射再合并，避免两套映射含义混淆。

QQ / 微信等不同 owner 的同一真实人通过独立 identity group 关联，须核对两份档案当前 revision、明确确认并记录依据。该组只表示身份等价，不授予来源读取权，不移动或公开字段，不把两个来源的好感分数相加。组内最多十个账号档案；两个已有不同组不会自动合并整组。

查询从 SQL 开始带 owner 与节点 / 字段 / 边权限，只返回有权节点。管理员管理页面可依法查看其管理范围；普通对话只按 Run 中服务端冻结的 owner 和真实会话读取。模型不会因管理员审计权获得整库资料。跨账号组中不可见节点的称呼与字段均不出现在另一来源的结果。

已核验当前发言者的相关档案用于 Native 上下文，记录实际使用的节点、字段 revision 及关系端点。仅凭姓名匹配不会绑定身份；提及人物的自动消歧和授权好友软件导入尚未开放。资料以不可信引用注入，不授予权限。

## 来源纠正与遗忘

日记事件或条目必须仍有权读取且 revision 完全匹配。沿用日记的撤权水位，重新开启来源也不会复活已撤权的旧事件。已失效日记、已删除记忆和未完成对话消息不能作为新断言证据。

来源更正 / 遗忘在同一事务中清空相关字段正文和旧版本正文、关系理由、好感原因，取消相关模型整理任务，并使已使用这些资料的上下文、摘要及尚未发送结果失效。运行中的物理请求租约由请求所有者释放，逻辑取消不会提前归还并发。

遗忘人物清除其称呼、字段、旧版本内容、身份别名、关系理由、好感原因和联系许可依据，解除跨账号映射。原始消息与离线备份有各自的保留及恢复流程，接口不会将在线查询失效表述为所有介质已物理清除。

## 显式来源模型整理

管理者可选择一个已有日记事件或条目，明确同意本次出域，并选择同域已核验的关系目标。来源必须已开启日记收集和模型出域授权。模型不读取未选择的其他私有来源；日记条目只提供事实栏，感受栏不作为他人事实。

每次最多八个字段候选和四条关系候选，目标最多十个人物。宿主冻结人物 / 来源 / 策略 revision 和删除 epoch，并在请求进行中及提交事务中复核。模型不能创建或合并身份、批准自己的候选、修改许可或发送消息。未知内容可返回空数组。

队列持久化的是来源引用及目标 ID / revision，不复制一份日记正文或目标称呼。候选正文只写有来源的待审断言。每来源域每天最多八次、全局每天最多二十四次；失败也计预算，排队最多三十二项。日记、日程和人物整理共用低优先模型准入，交互排队时让路，自动模型活动合计最多一个。请求具有四十五秒上限，模型输出最多二万字节。

当前提供显式选源整理；无人工选源的后台自动人物抽取保持未开放，不能把本切片称为自动采集全部交付。

## 好感与接收许可

好感为人物各来源域的独立有向状态。默认 0–100、初始 50、直接互动宽限三天、之后每日衰减一分；使用百万分之一分的定点分值及余量，查询频率不改变累计衰减。单次人工 / 真实直接互动变化最多五分，每日变化绝对累计最多十分。

直接互动必须引用已完成对话的用户消息，同一消息不能换幂等键反复加分。旁观、导入和自己的发送不能刷新最近直接互动。当前未在后台自动增加互动分，管理员可提交经证据验证的事件。

规则为版本化参数：初始分、上下界、每日衰减、宽限和停机补算上限可预演及保存。保存前按旧规则结算到生效水位，之后用新规则；新初始分只用于新档案，不重设已有分数。默认只对未观测的停机区间应用一次七天补算上限，并推进整个停机水位。普通查询不套停机上限，时钟回拨不倒退水位。来源遗忘按原策略版本及仍有效原始事件重放，并记录脱敏的分数重算原因。

好感不代表对方感受、人的价值或接收许可。管理者可以登记待核验的联系依据或撤销，管理登录不能自行将许可设为 `granted`。主动投递始终 `delivery_available=false`，仍需接收人许可、实际渠道能力、静默 / 睡眠 / 额度和 Outbox 独立验收。

## 管理 API 与操作

所有路径以 `/api/admin/v1/relationships` 为前缀，受现有认证、Origin、CSRF、请求大小和服务端授权约束。变更须带精确 `If-Match`；人物变更使用人物 revision，字段 / 边审核及遗忘用对应断言 / 边 revision，联系许可与好感规则各有独立 revision。建立新人物 / 新关系使用创建语义。

| 路径 | 用途 |
| --- | --- |
| `GET/POST /people` | 来源受控的人物分页查询 / 建立 |
| `GET/PATCH/DELETE /people/{id}` | 详情 / 更正称呼 / 遗忘 |
| `POST /people/{id}/assertions` | 提交字段候选 |
| `POST /assertions/{id}/review`、`DELETE /assertions/{id}` | 审核 / 遗忘字段 |
| `POST /people/{id}/identities`、`DELETE /people/{id}/identities/{identity_id}` | 核验 / 解除会话身份 |
| `POST /people/{id}/merge`、`POST /people/{id}/split` | 同域来源档案合并 / 拆回 |
| `POST/DELETE /people/{id}/identity-group` | 跨账号同人关联 / 解除，不转授 ACL |
| `GET/POST /edges`、`POST /edges/{id}/review`、`DELETE /edges/{id}` | 有向关系查询 / 候选 / 审核 / 遗忘 |
| `GET/POST /model-jobs`、`GET /model-jobs/{id}` | 显式日记来源整理与进度 |
| `GET/POST /people/{id}/affinity/events` | 好感事件与理由 |
| `GET/PUT /affinity-policy`、`POST /affinity-policy/preview` | 版本化好感规则及无副作用预演 |
| `PUT /people/{id}/contact-permission` | 待核验依据 / 撤销，不开放发送 |

前端采用人物列表、关系网络、人物详情三栏布局；窄屏按顺序纵向展示。当前页最多 50 位未合并人物按已审核关系聚拢，圆形大小表示当前页关联数量，不表示好感或权限。图中仅绘制两端均在当前页的已审核有向边，保留箭头；未审核、已驳回或页外关系不补造为连线。点击、Enter 或空格选择人物，与列表及详情联动，高亮其直接关联；支持缩放、拖动空白和重置视图。筛选移除已选人物时清空详情并丢弃迟到响应。字段及关系审核、可追溯依据、身份映射与拆分、好感规则预演及明确遗忘确认继续保留，规则与关系审核列表默认折叠。模型整理结果和保存成功分开显示，不将排队或候选等同于资料已经生效。

## 验证与运行

本地检查：`cargo test -p dshd relationships`；前端 `npm run typecheck`、`npx vitest run tests/relationships.test.ts`。2026-10-30 起按 [Windows 发布流程](development-workflow.md) 记录目标 Windows 构建、固定 SHA、健康 / 鉴权、真实模型与浏览器验收；旧 Linux 结果保留为历史。单测覆盖同名分离、跨域拒绝、待审与字段冲突、生日精度、有向边、来源遗忘、当前会话金丝雀、跨账号组的字段和节点隔离、策略版本、停机补算与重放等。

数据库与删除水位沿用整库一致性备份。含人物 / 来源派生信息的数据库只能回到声明理解对应 reader 能力的版本；不得用旧程序绕过字段权限或删除水位。代码切换与数据恢复分别记录。


## 关系网络交互（2026-10-26 后续调整）

参考 Connected Papers 的可见交互，以 DSH 靛蓝、灰蓝和柔和金色呈现半透明节点及关系连线。图仅接收当前页最多 50 位未合并人物和两端可见的已审核关系；待审关系不参与渲染或物理布局。圆点大小代表当前页已审核关联数量，不代表好感或事实可信度。

加载或重置后短暂展开并收敛；拖动人物时连线、箭头及文字使用同一坐标快照，真实关联的相邻节点轻微跟随，松开后停稳。悬停与键盘焦点预览关联，点击或 Enter / Space 才选择人物并加载详情，拖动不提交资料或关系修改。背景可平移，滚轮和按钮缩放，重置恢复默认布局。

动效只在当前前端页面按需请求帧，无后端 worker 或常驻动画计时器。物理运动使用有界步长和最多三秒的静止收敛预算；页面隐藏、离开及 `prefers-reduced-motion` 变化时回收动画帧。减弱动态模式直接呈现终态，并保留人工拖动与键盘操作。实际发布与浏览器证据见 [交互动效验收](relationship-motion-validation.md)。
