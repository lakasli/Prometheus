# Prometheus 迁移范围

用户选择“全新项目重写，旧数据保留备份”。新实例不导入旧 DSH 数据库，不要求旧 API 路径兼容。原 [完整架构](architecture.md) 的功能目标继续保留。

## 第八批日记周期与覆盖迁移（2026-10-31）

对照旧Rust `diary.rs`、`diary_aggregation.rs`、`diary_model.rs`和[日记契约](diary-system.md)，补齐事件账本、日期封存、固定日父版本的周/月目录、全部来源链、分层模型片段及最终归并、跨重启检查点和递归遗忘。采集与模型出域分开，进行中的日期标明截至当前，未观测和被跳过的民用日期不编造经历。普通Native对话增加有许可日记的关键词检索/近期回退及实际选取记录；此前只接了显式记忆。schema7保留旧人工资料、草稿、账本和日程；已有TS明确记录作有来源导入，原Rust数据仍不导入。跨来源的统一自我日记、人物字段/关系来源的完整对接、既有周期跨时区迁移及规模/长期运行仍待办，不称全部日记系统迁移完成。范围、失败与正式Windows证据见[日记迁移记录](prometheus-diary-validation.md)。

## 第七批日程逻辑迁移（2026-10-31）

对照旧Rust `schedule.rs`、`schedule_model.rs`与[日程契约](schedule-system.md)，补齐每日/每周/每月系列、原机会键与单次例外、此后拆分、整个系列修订、冲突预演、拖动待保存、月/周/日民用时区日历。新增明确文本资料、版本化自主授权、工作目标、规则/模型候选规划、阅读全局覆盖与重读generation；实际成功后才推进水位，撤销清理正文/笔记并中止旧请求。人工与自主来源、批准与实际执行分别保存，触发与整理只读投影不重复调度。schema6保留schema5账本与配置草稿。文字活动注册执行、渠道自主动作桥、视频/主动联系及完整日周月覆盖仍缺；不称完整日程或原M2/M4/M5。实现、已发现失败及正式版本验证见[日程迁移记录](prometheus-schedule-validation.md)。

## 第六批人物逻辑修复（2026-10-31）

进一步对照旧Rust发现好感策略追溯重算、缺每日绝对额度/停机上限，以及人物合并搬移事件并清空来源档案的问题。本批补齐固定点独立账本、分段规则、幂等人工调整、每日额度、宽限与停机水位，以及保留原档案/端点/账本的同域合并和明确拆分。schema5升级保留已有规则和当前分值，早期已清空的合并来源不推测恢复。真实互动来源绑定、自动归因和跨账号身份组仍缺，详情与正式验收见[人物账本记录](prometheus-relationships-validation.md)。

## 第五批补齐（2026-10-31）

持久配置草稿、独立字段校验、异步模型/QQ凭据检查、取消和操作回执已接通。草稿按账户隔离，内容版本与生效配置基准分别冲突检测；旧基准需核对差异再明确重新定位。保存/检查不自动应用，已应用草稿只读，重复请求返回原回执。检查占用真实请求槽，编辑、删除、取消及关机均待连接关闭后释放；重启不自动重放。schema4保留已有草稿，升级前快照及完整实例恢复路径见[配置流程验收](prometheus-configuration-validation.md)。完整功能仍未迁移完。

## 第四批补齐（2026-10-31）

已补上性格历史恢复管理入口（另存新版本，保留稳定身份），以及运行日志类型/状态/运行/文本筛选、游标分页、输入输出引用、Native模型上下文快照和30天/20,000条清理。遗忘、来源到期与上下文失效会清理快照，不复制正文到事件表；另修复授权过期即时复核、续期采集起点及QQ取token后回复窗口复核。schema3升级前自动备份，schema1/2旧制品拒绝打开新库；详情和正式验收见[日志与恢复记录](prometheus-journal-validation.md)。完整功能仍未迁移完；持久配置草稿后续由第五批补齐，隔离执行、附件、周期活动与真实资源验收等继续待办。

## 第三批审查（2026-10-31）

对照旧Rust源码及本机WSL独立运行实例审查后，确认**功能逻辑尚未完整迁移**。本批补齐FTS实际查询，修复整理前失败停留排队、多批日记资料来源上限、过期来源授权、遗忘后睡醒恢复旧回复、模型日记误标人工记录等问题。逐项范围、缺项及固定版本验证见[迁移审查](prometheus-migration-audit.md)。

Windows空权限原生探针已实现并编译；运行出现应用程序控制策略4551（CodeIntegrity 3077/3033）、启动失败及子进程初始化失败0xC0000142。**这不是隔离通过，语音、Harness、Python和Component执行继续禁用。** WSL仅供旧逻辑对照，不计入Windows执行能力验收。

第三批补充了清单此前未细分的缺项：持久配置草稿/异步操作状态、性格历史恢复管理入口、运行日志筛选/输入输出与上下文引用；后两项的补齐见第四批。多角色选择和角色卡写入已由旧项目单一性格决定停用，不作为应恢复的产品功能。

## 后续顺序

1. Windows独立worker隔离与生命周期，解除语音/Harness/插件的共同阻塞；证明之前保持禁用。
2. 常用图片、QQ/微信附件broker、QQ分片上传，再进行真实平台验收。
3. 完整自主活动、跨来源日记与人物观察，保留独立授权与来源水位；周期例外/有界阅读及有界日周月覆盖分别由第七/八批补齐。
4. 配置真实模型和平台资源，补充规模、性能与长期运行证据；合成结果不替代这些验收。

原crates、旧web/admin、历史部署脚本和未提交Breeze改动保留。旧数据库已有一致性备份，第三方库与素材保留原位。当前实现schema7；schema1/2/3/4/5/6升级前自动生成原版本数据库快照，正式升级另备份完整实例（含主密钥），实际部署以本批验收记录为准。旧制品拒绝打开新schema，回退须恢复匹配的完整备份到新目录。见 [Windows流程](prometheus-windows.md)。
