# 会话约定管理

约定是带来源的资料视图，不是发消息许可或执行动作。它复用 [可信会话状态](conversation-state.md)，主体、对象、事项、时间原话、确认、活动、执行与投递分别记录。

## 来源与状态

普通文字中的少量直接表达（如“请提醒我…”“我们约定…”）可产生 proposed 候选，不产生真实提醒或日程。引用、假设、疑问、否定与“可以试试”等不确定建议不自动确认为约定。敏感格式检查复用已有摘要检查；命中时不复制为新派生正文，不声称识别全部秘密或自然语言。

来源由真实 Run 的 owner、完整会话和实际发言者构造；昵称、同一性格或管理员全库审计权不授予跨源读取。未知群发言者可以正常聊天并冻结空引用，但不能继承他人的约定或成为可授权接收者。管理页只枚举当前管理员可管理的真实来源，不要求用户手填 owner、平台 ID 或 Run ID。

资料分别标明 speaker / assistant / joint / unresolved 主体与 speaker / assistant / unresolved 对象。用户承诺读书不因系统读了书而履行；对象不确定时保持未解决，客户端不能指定任意外发收件人。

`confirmed` 只表示真实管理员对资料进行版本化审核。`confirmation_evidence` 明确管理审核依据，并保持 `source_assent_verified=false`；不能把管理员审阅冒充原发言者或接收者同意。原话、时间精度、时区与可信消息锚点分开，无法解析的复杂时间保留 unresolved，不伪造精确日期。

## 真实活动与履行

确认不自动建立日程。只有核验同一稳定实例、owner、完整会话、真实授权与持久活动 / occurrence 后，才能关联既有活动并显示 scheduled。活动选择器按同一来源筛选，不拿管理员自己的活动列表替代 QQ 来源。提醒和外部联系缺少真实能力或接收许可时保持阻断。

关联活动的实际 planned / running / completed / failed / unknown 与结果另查；completed 仅证明关联活动有相应结果，不自动证明承诺履行、已发送或已读。`fulfillment_verified` 仍单独为 false，不能用一句模型承诺或人工按钮伪造履行证据。

取消资料和取消日程分开。请求同时取消活动时必须核对真实 schedule 结果；正在执行或 unknown 不假装撤销，不换幂等键自动重跑。资料到期不删除实际历史，遗忘 / 撤权按来源失效链清除派生正文并保留删除水位。

## 管理与模型边界

管理 API 为 `/api/admin/v1/commitments/scopes` 以及 `/conversations/{id}/commitments` 的读取、提议、详情、participants 审阅、confirm、关联活动和 cancel；活动候选由同会话的 `commitment-activities` 接口提供。写入要求真实管理员、Origin、CSRF、幂等键及相应精确版本。缺版本 / 版本冲突 / 无权限分别处理，不能依据浏览器隐藏按钮授权。

模型上下文仅选取当前同发言者有权使用的有界资料，按最终选择登记准确引用。已冻结请求在派发、媒体准备和发布前再次检查约定 revision / epoch / 来源；换版阻止旧结果发布，不提前归还在途 lease。

管理入口位于日历工具栏弹窗，日历、工作目标、授权三块和配置五抽屉保持当前产品结构。日志只读展示状态与上下文选择，不能发新消息、执行动作或恢复旧工作台。release reader 为 `commitments=1`；有数据、epoch、使用证明、删除或幂等记录后禁止盲降到不理解其语义的旧版。
