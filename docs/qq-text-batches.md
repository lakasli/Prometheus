# QQ 连续短文本合并

日期：2026-10-26，Asia/Shanghai。沿用同一助手及其已保存性格，不新增角色、常驻进程或模型。发布与验收以 [本轮记录](qq-text-batches-validation.md) 为准。

## 行为

仅合并同一官方 QQ C2C 私聊的普通短文本。每条须不超过 256 个 Unicode 字符和 1,024 UTF-8 字节；停顿 3,500ms 后允许开始生成，从第一条接收起合并等待最多 8,000ms，每批最多 8 条、合计 4,096 字节（含换行）。这不是模型排队、生成或投递的总耗时上限。到数量上限即结束等待；超出总字节限额的新消息另建批次。以上是本发布的固定策略，不是模型可以修改的参数。

例如依次收到“我今天”“有点累”“不想说话”，等待窗口内组成一轮输入，按顺序以换行保留，统一请求模型。模型可以按照原有逐句协议产生 1–4 个回复对象；一次统一回应不等于强制只发送一个气泡，也不会扩大 QQ 回复额度。

首条即时持久化为 queued Run；后续符合条件的消息只在该 Run 尚未开始、无请求快照和网络 lease 时追加。等待不持有模型并发槽，不为每个会话启动计时进程。模型已开始或逻辑取消但网络 lease 尚未释放时，不重写其请求；后续消息另建批次，并沿用既有同会话并发限制。

## 边界与来源

- 仅选当前会话绝对最后一个 Run，不能跨过命令、媒体、Skill、长文本、未知 `/` 指令或其他消息类型寻找旧批次。其他 QQ 渠道、Web 和微信不新增合并行为。
- 账号、私聊对象、来源 owner、凭据、完整冻结配置 / 性格快照或记忆可见水位不同，均不追加。即使性格内容相同，保存产生的新 revision 也是边界。
- 接收时间采用持久 `qq_received_events.received_ms`，不使用平台正文伪造的时间，也不把媒体下载或接收积压的处理时刻当作新到达。旧回执无毫秒字段时以原秒级时间回退；已超过窗口的积压输入不重新等待。判定追加时处理时刻也必须在原窗口内，接收或处理延迟可能使内容另建批次，不承诺按用户手机发送间隔必然合并。时钟回拨结束等待，不无限延后。
- 命令 / 媒体等边界立即封口前批次。同会话模型 worker 不越过更早 queued Run；既有立即完成的本地控制回复 / 媒体提示仍可能先于模型回复发送，不宣称所有 Outbox 全局严格 FIFO。

`qq_text_batches` 保存首末接收毫秒、静默截止、片数、字节及遗忘水位；`qq_text_fragments` 不可变保存每条原文、消息 ID、来源、顺序与接收时间。原始独立 Inbox 事件都指向同一个聚合 Run。聚合 `runs.input` / user 消息由换行连接，user 消息时间取最后片段接收秒数；原始每条时间不丢失。模型快照另带 `DSH_QQ_TEXT_BATCH_V1` 来源说明，完成后仍由现有日志查询聚合输入及请求快照。

事件键和每条原始平台消息 ID 都参与持久去重，完成后的片段也保留。同消息改 event_id 重投不会多加一段、延长窗口或再次生成。接收、追加、Inbox 与消费 fence 在同一数据库事务完成；重启后未开始的批次继续等待或立即到期，已开始请求仍依原有 interrupted / unknown 规则处理，不自动重发。

片段正文沿用既有 QQ 入口去平台提及 / 首尾空白的规范化；这里的原文是每条独立正文，不是包含附件凭据的完整原始网络包。

## 回复、容量与恢复

合并 Run 的被动回复目标更新为最新一条实际接收的合法消息 ID 及该消息自身的原始截止时间，不沿用旧 ID 人为延长期限。整个批次只有一个 Run / Outbox，仍受四项回复、实际完成间隔、凭据复验、取消及未知结果不重发约束。

若边界需要新建 Run 但全局 / 会话运行队列或控制回复队列已满，返回内部可重试容量状态，接收消费者保留已确认回执的正文、配置、原始时间和截止，500ms 后重试入队；这只针对模型请求之前的容量不足，不重试模型或消息投递。单消费者此时施加背压，可能延后其他来源；原始被动期限届满仍按既有 expired 策略记录，不无限保留待处理附件或扩大队列上限。

独立批次 Schema 使用版本标记，不提高通用 runs/messages 的 reader。只要批次或片段有数据，代码回滚就必须具备 `qq_text_batches=1`；完成记录也不能绕过，以免旧程序无法识别后续片段消息 ID。空表可兼容旧版本。兼容检查在停止服务后再次执行，防止在线检查后首条新批次写入产生竞态；拒绝手动回滚时保留原指针和数据，恢复原运行状态。

性格、稳定 assistant identity、配置和用户历史均不在本轮重置。恢复代码与数据分开处理，不通过清空片段或用户记录绕过兼容检查。
