# 会话隔离、投递历史与生成中更正

本契约对应 `architecture.md` 第 5.4–5.7、9.10 与 18.2 节。实现与真实验收分别记录在 [本轮验收](conversation-coordination-validation.md)，不以文件存在或模拟回执宣称真实渠道通过。

## 身份与来源

入队事务保存 Run 的真实 owner、完整会话、账号及固定受众；发送目标必须与服务端确认的来源一致。QQ 逐条发言者由已鉴权事件记录，群内成员不冒充群域，也不带入成员私聊。模型只收到有命名空间的摘要引用，不收到平台原始 ID、回复凭证或登录凭证。

实际编译 Prompt 时冻结身份、来源策略、删除水位及已核验人物映射版本。旧快照不能通过补写新权限而变成有效请求；授权变化时停止使用旧证明。历史、日记和人物资料仍分别执行原有来源过滤；同一个性格、同名或跨账号同人关联不授予历史读取权。未启用的 Harness、观察来源或媒体能力保持原门禁。

## 投递证据

生成结果与实际投递分开。原始模型结果保留为受认证的运行审计，普通后继请求按每一段的真实状态投影：

| 事实 | 可进入后续对话的内容 |
| --- | --- |
| QQ 有合法平台回执的文本句段 | 实际已受理的该段文字 |
| QQ 仅部分句段成功 | 成功句段；其余只记录 queued、sending、failed、expired 或 unknown 等事实 |
| 微信成功业务回执 | 实际受理文本；超限降级使用真正发送的固定短文，不用原始长候选代替 |
| 图片、语音、视频受理 | 媒体种类和回执证据；图片只投影实际发送范围内的说明。没有合成文本对应证明的语音、视频不虚构文字内容 |
| 未尝试、明确失败、已过期或已抑制 | 保留用户原问题，不把候选答案当作双方已交流的内容 |
| unknown | 保留结果未知，不推断已送达或未送达，不自动重发 |
| Web / CLI 本地完成 | 保留本地完成语义，不扩称渠道平台回执或用户已读 |

每次请求与 Prompt 同事务冻结 `DeliveryContextSnapshot`。晚到回执只影响之后的新快照，不改写已在途请求。快照仅存引用、版本及摘要，不另存正文。对话 API 对已抑制候选返回明确发布状态，原始结果仅作为运行审计保留。

摘要采用同一投递投影，并校验所有累计来源版本；晚到回执使旧摘要失效后从有效来源重建，不推进遗忘水位而丢掉原问题。日记等待仍在发送的回复结算，再采集用户原文、已确认回复及真实投递状态。已有日记遇晚到回执按有界脏队列修订；人工更正、遗忘和撤权优先，不自动复活。升级在提供服务前清理旧自动日记中未经证实的候选正文；旧无投递快照摘要保留审计但不继续供模型使用。

## 更正与发布

同会话输入具有持久单调序号、前驱及发布 revision。首批采用保守的封闭明确表达，例如“等等，改成明天”“刚才那个数字是 23”“上一条不用回答了”；引用、疑问、假设、“谢谢”和另外一个问题不触发撤销。归属不明确、群/频道、媒体、Skill 或缺少可信前驱时不自动抑制。

明确更正只关联同来源唯一前驱。纯文本旧请求尚未发送时，记录旧候选不再发布，后继请求携带原问题和更正。已经成功发送的片段保留；只停止尚未领取的后续片段。发送中、unknown、媒体或工具动作已开始时保留待核对状态，不伪称撤销外部事实。

生成完成、Outbox 建立及领取发送都在事务中复核发布决策。更正不修改旧 Prompt、不重写原消息、不把 Run 状态冒充外部取消，也不提前归还尚未结束的模型请求 lease。完成的旧候选可以留在审计中，但不得重新排入 Outbox 或通过摘要和日记绕回后继上下文。

## 数据与回退

新身份、投递、摘要、日记投递与发布决策表由 release capabilities 门禁保护。包含这些语义的数据库不能盲降到不识别它们的旧制品；升级前进行 SQLite 一致性备份，代码回退与数据恢复分别处理。真实配置、性格、来源授权、联系许可和用户数据不因程序升级而自动改写。

本轮不代替后续话题焦点、结构化约定、睡眠、主动联系和 Python 动作的独立实现与验收，也不将协议模拟记为真实 QQ / 微信客户端通过。
