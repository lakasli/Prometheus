# Prometheus 人物来源与身份迁移

2026-10-31，Asia/Shanghai。对照旧 Rust `relationships.rs`、`relationships_groups.rs`、`relationships_model.rs` 与[人物契约](relationships-system.md)，继续补齐第六批之后的来源字段和身份链路。本批正式固定 SHA、恢复演练和 Windows 运行证据在实际执行后追加。

## 实现范围

- schema8 保留原有名字、备注、同域合并映射、独立好感账本及其固定点余数；只给已有管理账户的人物建立管理元数据和兼容名称版本，不推测旧备注的字段、来源或核实程度。新建来源域人物须选择实际可访问会话，服务端推导归属，不能指定任意 owner。
- 姓名、昵称、年龄及陈述日期、生日历法/精度、工作、性格、爱好、偏好、约定分别保存来源版本与审核历史。年龄不推算出生年，农历不擅自换算公历，月日不补年份。新字段和有向边先待审核；本人陈述、第三方转述、推测、人工核实标签在批准后保留。冲突需明确提供全部被替代断言的 ID 与当前版本。
- 人工、完成用户原文、记忆、日记事件和周期日记提供来源证明。排除本地控制命令、自动任务、未完成请求及本人候选回复；消息以不可变正文版本1标识，不用因其他上下文操作而递增的 epoch 冒充正文版本。采集及模型许可分别核验，历史消息必须在授权起点之后。日记来源只取事实正文，不把感受转换为他人事实。
- 来源更正、遗忘或许可版本变化会清除当前和历史字段/边正文及依据，保留无正文状态记录和版本水位；旧来源不能再次提取。新版记忆/事件可由用户重新明确选取。人物整体遗忘另外清理名称历史、身份别名/依据、联系证据及身份组历史依据；原聊天和离线备份保留。
- 修复原有普通人物更正、人工好感及合并操作推进整个人原文删除水位的问题。记忆/日记更正及真正遗忘仍保留原有水位保护；常规人物资料修改不再使无关日记原文失效。
- 身份绑定须独立核对实际同域私聊/本人会话；群、频道不代表一个人，同名不自动绑定。跨账号身份组最多10人，核对两个人物和组版本，拒绝自动合并两个已有组；组不合并字段 ACL、好感分或联系许可。有关联组的人物先拆分关联才可同域合并。同域映射继续保留原资料，普通对话读取可见映射成员而不搬移原字段或账本。
- 普通 Native 只读取明确绑定当前会话的说话者、同域/共享可见成员及批准、有效、获模型许可的字段和有向边。最多30个字段、20条边，有界 JSON；未知/隐藏成员不进入名字、字段或图端点。实际请求才记录人物/字段/边版本，隔离任务不读取人物。更正、到期、解绑及来源失效清理相关会话快照/摘要、取消在途旧回复并抑制未发送候选，物理请求槽仍按原连接关闭释放。
- 联系许可仅能记未授予、待验证或撤销；待验证须指向当前核对绑定，不能由管理账户强行变成渠道已授权，主动发送始终不可用。
- 管理页在人物和人际关系中提供来源域建档、字段/边审核与版本记录、身份绑定/关联/拆分、联系记录。关系图只显示本页最多50个未合并人物及两端可见的批准边，支持缩放、平移和拖动；列表提供等价操作，减少动态效果偏好生效，未保存表单有离开保护。
