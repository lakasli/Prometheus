# Prometheus 人物账本迁移验收

2026-10-31，Asia/Shanghai。第六批继续对照旧`relationships.rs`与`relationships_affinity.rs`，发现旧TypeScript切片虽有“好感”和“合并”名称，行为并不完整。本记录的固定发布结果在实际执行后追加。

## 发现与修复

- 旧TS每次用当前策略重算全部事件，改变初始值/衰减会追溯改变旧分值。本批使用百万分固定点状态、余数和单调结算水位；规则变更事务内先结算旧区间，再明确确认新版本和依据。新初始值只用于之后新建人物，上下界修改只作显式裁剪。提供认证预演和策略历史。
- 新人物恢复旧Rust默认：50初值、0至100量表、每日衰减1、3天宽限、停机补算最多7天、单次5及每日绝对累计10。已有自定义规则和既有人物当前旧算法值在schema5初始化时固化保留；原向零衰减作为兼容模式，不用新默认覆盖。旧策略在历史上曾改变造成的追溯影响无法凭空重建，升级保持切换时的实际状态。
- 人工调整要求If-Match、明确审核与幂等键；相同请求重试返回已存结果，不重复扣额，不同内容复用键冲突。额度按UTC自然日累计请求变化绝对值，即使被上下界裁剪也计额。人工理由不等于直接互动证明，不更新last_direct_at；真实互动必须等人物会话绑定和来源校验迁移，当前返回503。
- 心跳每10秒记录观测运行，恢复时先结算已覆盖区间、对未观测间隔只补算上限，再将整个间隔推进水位；重复恢复和重启不重复扣减。没有以定时衰减建立模型worker。
- 旧TS合并清空来源payload、搬移事件并改写关系端点，无法安全拆分。本批只保留同域身份映射，两档案版本同时核对；原资料、端点和独立账本不移动、不相加。明确确认及依据后可拆分；拒绝链式/带子来源的合并。遗忘根档案前须拆开活跃来源，来源遗忘清理自己的事件理由、详情和状态，不影响目标独立分值。
- 早期TS删除式合并的来源已不在当前库，不猜测恢复或重新归属事件；认证管理页显示历史不可逆提示，需另行核对原完整备份。新合并/拆分的私有历史保留依据，任一端遗忘后清空依据。跨账户档案不可读写，不由合并授予来源、模型出域或发送权限。
