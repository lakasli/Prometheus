# Prometheus 明确记录入账与大来源整理

2026-10-31，Asia/Shanghai，第十七批。原功能仍未全部迁移；当前逐项边界见[完整性核对](prometheus-completeness-audit.md)。本批处理第十六批审查中实际复现的合法长日记漏账，不导入旧Rust数据库。

## 范围

旧入口允许日记正文16000、标题200、感受4000个UTF-8字节。此前拼接后的来源受12000字节限制，异常被吞掉，保存201也可能完全没有来源事件。现在保留原字段上限，原记录和来源/入账状态在同一事务保存；数据库错误使整个写入回滚。敏感内容、派生视图、已审核模型视图、非管理来源等保留原记录并显示固定排除原因，不作为新原始事实复制。已遗忘的来源不得重新生成。

日记标注原参考日期、日/周/月区间、上海参考时区及原创建时间；导入时点不冒充当时已观测全天或已完成周期。接收分区使用其他时区时保留原参考历法。旧的有效来源事件不因补录改写正文或版本。更正维持来源身份，旧版本正文、模型片段及派生结果清除；遗忘同样递归清理。

schema15升级前自动生成原schema快照，并将明确记录扫描游标归零，空闲时每批最多64条，补查旧游标之后及此前被跳过的记录。新睡眠受理时冻结所有相关原记录的ID/版本/顺序，采集使用冻结引用，后续新增或更正不混入旧批。升级中的schema14睡眠严格沿用原快照，不为它补造新记录引用；后续新睡眠才接管旧漏账记录。备份仍须包含数据库、主密钥和其他实例文件，旧14制品拒绝打开15，代码回退须配合匹配的完整数据恢复。

单条来源转义后也可能超出实际模型输入预算。现在保留原外层来源序号及digest，将该条序列化JSON按UTF-8边界分片，再按实际请求字节、配置上下文和provider窗口分批归并。持久化的只有版本、范围、digest和已验证模型摘要，不复制原文片段。局部请求不标全天完成；完整来源汇合后才能参与外层归并，最终周期完成仍走原来源/许可/删除水位复核。分片不增加来源数，成功请求不重发、不重复计费；未完成请求仍计入实际尝试和预算。过小预算或不收敛明确阻断，不循环调用。预算耗尽、重启、睡醒只保留已完成检查点，不延长原wake_at。新睡眠接管上轮已中断任务时清除旧等待时间，预算仍重新复核。

另修复兼容日记直接进入Native上下文绕过模型许可的问题：在SQL候选选择前检查当前分区/grant，撤销后不由旧式视图兜底。明确记忆原有召回语义保留，秘密模式和当前已知凭据在选入上下文前再次过滤。管理页分别显示原记录、来源入账状态和排除原因，模型分片状态不能当作完整周期结论。

## 验证口径

新增16个后端场景，覆盖13000字节反例、全部最大字段、SQL失败事务回滚、CAS更正/遗忘、95条旧14记录跨页补录、冻结后更正/新增、实际HTTP分片体积、较小配置预算、成功片段重启续接、睡眠额度耗尽后恢复、在途物理lease、跨时区参考信息和另一已认证管理者隔离。预算日切换使用合成账务时间，不提供生产重置接口，不记成真实跨日运行。

浏览器新增第23个场景，通过真实页面保存13000字节正文和脚本文本，核对原记录与来源链接、排除状态及320/1440宽度；内容按文本显示。原22个场景继续回归。合成loopback模型仅证明协议、来源、预算和状态流，不证明外部模型质量或真实QQ/微信收发。

本地构建、固定SHA制品检查、固定包测试、旧14成功检查点兼容演练、完整实例升级/回滚及正式运行结果分别记录；正式切换证据随后补充。本批没有新的Windows worker隔离证明，语音、Harness、Python和Component执行继续不可用。跨来源统一日记、非管理来源的独立许可整合、既有周期跨时区迁移、201条单日来源上限和真实规模验证仍待完成。
