# Prometheus 人物映射与关系图迁移

2026-10-31，Asia/Shanghai。继续对照旧Rust `relationships.rs`、本仓库旧前端 `relationship-graph.ts` / `relationship-graph-motion.ts`及[人物契约](relationships-system.md)，补齐来源域映射和关系网络交互。未引用第三方图形源码或新增动画依赖。本批保持schema10，正式固定版本、备份和运行结果在执行后追加。

## 权限与映射

原TypeScript合并/拆分入口把登录者直接当作来源owner，无法管理已授权QQ/微信来源的人物；同owner但不同可见范围也没有拒绝。本批统一通过人物服务核对操作者对两个端点的管理权限，再从服务端记录读取实际owner，要求相同owner和相同private/shared范围才允许新合并。共享只读不变成管理权限，客户端不能指定owner。新人物详情入口和保留的旧入口走同一检查。

合并与拆分核对两个档案的当前revision，要求明确理由与确认；身份组须先解除，不允许循环、链式映射或把已有子映射的主档案再次并入其他人。映射不移动或覆盖原字段、身份、关系端点、联系许可、来源和独立好感事件，不累加分数。来源owner仍保存于映射记录，实际操作者写入审计。新字段候选引导至主档案，旧来源字段继续保留且可审核/遗忘；映射变更清除旧Native上下文。

早期同owner跨可见范围映射仍可由同时管理两端的人明确拆开，拆分只移除映射，不扩大权限；不批量改写已有用户数据。早期已清空来源的删除式合并仍无法安全推测恢复。

管理页提供同域目标、两个版本、独立核对确认及明确拆分。共享只读人物不展示修改入口。列表与图从同一个鉴权分页快照读取，包含本页合并来源供管理、图中只显示本页未合并人物；最多50个节点，已审核有向边必须两端都在此页。待审关系和页外端点不参与布局，圆点大小只表示当前页关联数量。

## 交互与生命周期

宽屏采用人物列表、关系图、人物详情三栏，窄屏按顺序纵向。复用本仓库旧前端的确定布局、碰撞分离、圆边裁切箭头和双向边分弧；使用新TypeScript服务的字段/来源契约，不依赖旧前端运行时。节点、边、文字共用同一坐标快照，加载或复位短暂展开后停止；拖动节点时真实邻居轻随，松开后收敛。布局与拖动位置只保存在页面，不提交人物或关系修改。

悬停/聚焦预览联系，不请求详情；点击、Enter或空格才选择。拖动有移动阈值、精确viewport逆变换及释放后的短暂防误选，pointercancel和捕获丢失释放拖动。背景平移、滚轮/按钮缩放、复位、选中与邻接强调均保留。动画使用有界步长及最多三秒物理预算；空闲、收起、隐藏、离页和减弱动态变化回收帧。减弱动态保留静态布局及人工拖动，不请求动画帧。

列表筛选或翻页移除所选人物时清空详情、审核版本和未保存的子表单。详情请求使用取消和请求代次/当前页/人物校验，迟到响应不能恢复旧人物；管理页离开时取消请求并释放动画。未保存选择的离开保护继续生效，不为历史人物创建常驻进程。
