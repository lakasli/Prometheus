# Prometheus 日志与性格恢复验收

2026-10-31，Asia/Shanghai。本批对照本机WSL旧实现补齐性格历史恢复及日志，不代表全部功能迁移完成。前批审查与Windows worker阻断继续见[迁移审查](prometheus-migration-audit.md)。

## 行为与安全边界

- 性格页历史版本可明确恢复，使用当前If-Match创建新版本；稳定身份、记忆、模型配置及已入队Run不改写。
- 日志支持类型、状态、Run、文本、1–100分页大小与游标；文本是字面搜索。来源为本人Web和实例渠道，不能借事件引用读取其他账户Run；匿名请求拒绝。稀疏查询达到每页4,000条扫描上限时仍返回前进游标，避免隐藏更早的匹配。
- 事件只存原消息/Run引用与受控标题。输入/输出按引用解析；输出标记“生成候选”，不声称平台已送达。实际Native消息上下文快照先隐藏已知凭据；查询再隐藏当前已知凭据。正文显示上限16KiB，明确标注截断，不宣称精确token数。
- 纠正、遗忘、来源授权过期和睡眠重置会清理prompt快照；旧日志只剩元数据，原聊天和备份按原契约保留。保留30天、最多20,000事件，删除context事件时同步清理快照。其他模型整理任务仍使用原审计，没有虚构完整上下文或ASR/子任务/worker事件。
- 发现并修复：过期grant不能只依赖250ms定时清理；认证操作、Native入队/调用/发布、渠道发送边界均即时复核。续期不能保留已过期采集起点。QQ取得token后再次核对作息、来源上下文和被动回复期限；若此时入睡，未开始POST的有效回复重新排队，睡醒再复核发送。来源撤销/期限到期阻止派发。此检查用合成协议验证，不计作真实平台通过。
- 视觉描述等待期间发生失效时，Native不得重新保存旧快照或继续请求文字模型。请求前上下文复核失败也要从queued转为终态，不能无限排队。

## 数据升级与恢复

schema3新增prompt_snapshots、日志引用/状态/保留触发器及索引。schema1/2升级前VACUUM原版本快照；DDL、元数据版本和一次性历史消息引用回填在同一事务完成。不存在实际历史上下文的旧Run不补造模型请求。制品build.json和release.json记录data_schema，旧schema1/2制品拒绝打开3。

正式升级须在正常退出后完整备份数据库、主密钥和其他实例文件，核对NTFS ACL；失败保留新目录，在独立私有目录恢复完整旧备份并用上一版固定SHA复验，不覆盖新数据。固定SHA与实际恢复演练结果在发布后追加。

## 本地检查

类型和前后端构建通过。针对性检查覆盖日志权限/过滤/游标、字面搜索、秘密隐藏、遗忘清理、视觉等待失效、预请求失败终态、20,000条保留、无定时器到期、续期起点与schema2升级；QQ覆盖取得token后到期/授权过期不得派发。浏览器覆盖历史恢复、日志正文/上下文和移动宽度。最终全量计数与固定制品证据在验证完成后追加。

开发首轮严格类型发现可空owner/游标捕获，修复后通过；浏览器首轮日志select缺少独立可访问名称，补充aria-label后通过。截图关闭取样时的CSS过渡动画，避免记录侧栏移动中的中间帧；不修改生产动画或安全策略。
