2026-10-31，Asia/Shanghai。对照固定旧Rust `df6429cbceb8f16504efe9464c1abbbdb4a67e29` 的 `daily_life.rs`、`chat_reply.rs` 和[通用安排契约](general-plans-images.md)，补齐普通Native回复中的有界文字成果登记。用户未提交的Rust/Breeze改动不作为可覆盖的迁移来源。数据库升级为schema11，正式部署证据执行后追加。

## 已迁移逻辑

普通Native回复可附带唯一 `self_activity` 决定，宿主提供最多3个既有授权内的10分钟空闲时段，至少保留7分钟缓冲。模型只能选择本次时段、80字内标题和3000字/12000字节内完整正文，不能指定owner、权限、路径、执行命令或完成状态。严格完整JSON、重复字段、未知字段及媒体类型校验；仅兼容内容和字段完全相同的前置文字数组与唯一安排对象。正文作为字面文本保存，不执行其中代码或访问URL。

回复与安排在同一最终事务受理，重新核对来源、授权版本、实际空闲、额度、睡眠及上下文版本；新冲突使两者一起失败，不擅自换时间。已有同来源、同正文、同授权的待执行安排不重复占用额度，暂停、取消、遗忘不返还已有分配。普通人工writing活动仍须已登记成果才可执行，旧授权和日程不会凭升级获得执行证据。

普通回复可能遗漏安排字段时，最多追加一次20秒/4096输出预算的语义核对，只发送本轮已生成回复及公开可选时段，不追加聊天历史或授权私有标题；沿用原物理请求槽和取消信号。先持久化尝试，再请求；未确认、取消、退出或重启不重复请求。引用、过去、条件、愿望及建议不自动登记；无法落实的新物理承诺阻止发布。中文词法仅作请求筛选，不是意图决定权，也未证明所有语言和通用自然语言动作均能识别。

文字授权可选绑定一个已核对私聊来源，不绑定时只作用于管理者本人聊天。QQ/微信来源还须分别获得采集和模型出域许可，且仅作用于许可之后的新消息。实际来源owner、管理者和当前说话者保持独立，不借用其他账户的writing授权。普通前台回复自身允许上述一次有界核对，不由此获得后台模型、自主外发或任意执行权限。

成果最初为prepared，到授权窗口内、宿主时钟可信且awake时实际保存后才记saved和真实时间；不把准备完成当作执行完成。已保存成果不因writing授权自然到期而消失，来源撤权、更正、遗忘仍清除正文及所有已有派生副本。只有既已开启的同来源private日记策略可记录不含标题和正文的通用完成索引，不建立新采集许可，不向shared日记复制渠道成果。

遗忘清除成果、核对缓存、日程历史/例外/幂等回执内的生成标题和执行结果、私有索引及其递归派生；失效上下文并中止在途请求。真实保存时间、原聊天与离线备份如实保留。管理页分别展示准备/实际保存、时区、来源及字面正文，独立版本校验和明确遗忘；分页和离页取消不保留常驻任务。

普通文字数组最多4段，宿主将后续间隔限制在1500–8000毫秒，并从上一段实际HTTP确认后重新计算，只有正常回复进入Outbox，成果正文不外发。unknown仍不自动重试。另修复模型明确以length等原因结束时，Native/自动阅读/笔记及其他通用模型调用不得发布或推进水位；未返回finish_reason的旧兼容响应不作为完整结束的严格证明，带安排及语义核对必须明确stop。

最初测试暴露日记采集夹具30秒扫描尚未触发、单日额度测试实际仍可合法安排次日；分别修正夹具扫描起点和授权horizon_days=1，未放宽生产限制。实现期间修复实际规范化日程定义与构造对象字段顺序不同导致哈希失配、撤权清理后响应revision过期、保存后授权到期错误清除合法成果等问题。原失败/通过日志分别保留。
