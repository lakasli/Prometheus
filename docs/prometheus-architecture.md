# Prometheus TypeScript 架构

2026-10-30 用户授权：使用 TypeScript 重写并改名为 Prometheus，作为全新项目运行，旧数据保留备份。本文件描述新实现；[原架构](architecture.md) 的完整功能目标继续保留，不回写历史验收。

| 层       | 当前实现                                                              |
| -------- | --------------------------------------------------------------------- |
| 运行时   | Windows 原生 Node.js 24.7–24.x，ES modules                            |
| 后端     | TypeScript strict，构建为 JavaScript                                  |
| 生命周期 | 官方 TypeScript Cordis 3.18.1；当前仅可信内置队列插件                 |
| HTTP     | Node HTTP / HTTPS，认证 API 与静态管理页同源                          |
| 页面     | Vue 3、TypeScript、Vite，新 `apps/admin` 工作区                       |
| 数据     | Node SQLite，WAL、FULL synchronous、secure_delete、版本化 schema      |
| 认证     | Argon2id PHC、随机会话、服务端 CSRF、8小时到期                        |
| 凭据     | AES-256-GCM 私有文件、独立主密钥、NTFS ACL                            |
| 模型     | OpenAI 兼容公共 HTTPS 文字协议，连接时校验真实 DNS 地址               |
| 执行门禁 | 语音、Harness和插件执行返回503；媒体模型显式配置，不加载不可信npm插件 |

新运行链路不编译或调用 Rust。WIT / WASM、Python 动作和 Harness 目标仍保留；后续由 TypeScript 宿主调用经 Windows 验证的独立 worker，不退化为宿主进程内执行。

## 数据与权限

`metadata` 保存 schema 和稳定性格身份；`admins` / `sessions` 保存管理身份；配置与性格各有不可变版本历史。`conversations`、`runs`、`messages` 保存对话与运行；持久队列与进程内物理请求 lease 分开记账。

`records` 按 kind 分别校验记忆、日记、日程、人物、关系和 Skill，不接受任意执行字段。资料默认私有、按账户隔离；共享记忆须逐次确认发布。其他域当前仅私有。配置权限不代替渠道接收方同意或外发授权。

更正与遗忘增加上下文 epoch，取消受影响的排队及在途请求。遗忘清空当前内容、全文索引和递归依赖的派生资料，原始对话与离线备份保留。中断模型请求不盲重放，旧渠道发送状态不导入。

## 网络与秘密

后端只监听 loopback。管理写操作同时验证 Host、精确 Origin、会话与 CSRF；Cookie 为 HttpOnly / SameSite=Strict，HTTPS 必须使用 Secure。静态文件解析后检查实际路径，不提供源码、数据或任意文件入口。

模型不跟随重定向；凭据只放授权请求头。请求字节、历史数量、响应大小、超时与并发均有上限；连接时拒绝受保护网络。loopback 模型例外仅能显式在开发 / 合成测试启用。上游错误正文不进入日志，已知凭据在输出中隐藏。

完整功能仍待继续迁移，见 [迁移表](prometheus-migration.md)。基础版不能记为完整 M2 / M4 / M5。

## schema7日记账本与周期覆盖（2026-10-31）

Diary将明确事件、完成互动和周期正文分开：按稳定身份、来源分区、owner/manager、可见范围和IANA时区生成确定性周期ID。默认自身私有分区，不自动授权聊天或模型。已有TS采集grant按原授权水位建立分区；人工记忆/无派生来源的人工日记保留原资料并登记来源事件，模型候选和已派生日记不回灌为新经历。旧Rust数据库仍保留备份、不导入。

统一Automation tick在可信时钟下执行有界采集与当地00:05之后封存；无独立常驻计时进程。持久日期检查点、固定7/31日父版本、全量原始来源关系与分层归并片段分别记账；月记不叠加跨月周记。单日最多200来源，周/月来源链无200条截断。成功片段保存范围和摘要，只有最终归并覆盖本层全部单元后发布模型正文；缺父/不完整父先等待，继续检查其他就绪任务。进行中的日期只表示截至当前，空日期按实际观测或民用历法跳日说明，不让模型编造。

每请求完整provider JSON最多48KB、2400输出token和45秒，单来源owner滚动24小时8次、日记全局24次，并共享已有全局调用额度、自动单槽和总并发2。失败/取消/未知消耗计数保留，连续失败3次后须明确重试；成功重置本批失败数。finish_reason长度/过滤/工具等非正常结束不发布，严格完整JSON拒绝重复/未知字段。诊断仅保存固定枚举、hash、字节、覆盖、状态与错误码，不保存模型回复。

日记事件与版本使用独立FTS供认证管理检索；只有模型出域许可有效时才产生Native可见records投影。Native按实际问题检索日记，无命中时最多补四份可见日记，标注recent_visible_day，事实/感受分别按UTF-8边界摘录，完整JSON不超过8KB；实际ID/版本/选择原因写入context_selections，隔离运行不接入。撤权、过期、更正与遗忘清理当前正文、全部派生版本、片段、索引和后续上下文；原聊天与离线备份另行保留。人工周期锁定不被自动改写，来源失效后需核对当前版本明确重建。详情见[验收记录](prometheus-diary-validation.md)。

## schema6日程系列与授权阅读（2026-10-31）

ScheduleCalendar保存owner/稳定身份/人工或自主创建者、定义修订、原nominal_at例外与实际机会快照。GET日历按IANA时区展开月/周/日，触发与整理仅投影，不重复调度；拖动只返回待保存的单次预演。实际执行/部分进度历史不随系列改期覆盖。此后拆分保留剩余名义次数；无效月日及DST缺失/歧义跳过，计入重复次数，不补到其他日期。首次冲突检查及默认规划有界，不能推称多年全量优化。

Schedule沿用原Automation tick与可信时间/清醒条件，不新增常驻调度进程。明确UTF-8正文资源、版本grant、工作目标与保守预算各自持久化；模型只能选择当前提供的资源/时段ID，提交前重新复核版本、冲突及权限。超范围草案需认证人工明确批准整个保存系列；定义/例外变化使批准失效，暂停恢复不替代批准。普通渠道Native尚未接入此自主动作桥。

阅读按4096 Unicode码点分片，以owner+资源ID+内容hash保存全局覆盖和显式重读generation。每次请求同时持有全局与共享自动lease，网络关闭后释放，错误/取消不退还保守预算；成功并核对fence/版本/来源后事务提交笔记和水位。撤销清空正文、全局游标及已有笔记，中止在途结果；重启attempt标interrupted并保留partial，不自动重放网络请求。schema5升级不重新初始化已有好感账本；升级前数据库快照和完整实例恢复分别验证。能力范围和发布证据见[日程记录](prometheus-schedule-validation.md)。

## schema5人物账本（2026-10-31）

affinity_states保存百万分固定点分值、结算水位和余数；规则切换前先按旧策略结算，新增不可变策略历史，初始值只影响以后新人物。affinity_event_details保存幂等键、请求变化和策略版本，每日绝对额度按请求量累计，边界截断不归还额度。人工调整不伪称真实互动，不重置直接互动宽限。十秒心跳与停机补算水位使同一离线区间至多补算一次；仍未接通人物会话绑定和真实来源计分。

新人物使用旧Rust默认50/0–100、每日衰减1、宽限3天、停机上限7天、单次5/每日绝对累计10。schema1–4升级前快照，首次账本初始化将既有旧算法当前值固化，保存原自定义规则和兼容向零模式，不用新默认重算旧资料。person_aliases仅建立明确映射，不搬移记录、关系端点或好感事件；原档案保留，可核对版本后明确拆分。合并链和有来源子档案的再次合并拒绝；遗忘根档案前须拆开活跃来源。早期删除式合并无法证明原资料或事件归属，明确标记历史不可逆，不能凭目标档案造回原数据。

## schema4配置草稿与操作（2026-10-31）

config_drafts以owner_id隔离，保留不完整但结构安全的编辑内容、独立内容revision及base_revision。保存不改变config_revisions。校验、连接检查与明确应用分开；应用事务内复核两种版本与凭据/执行门禁，产生不可变配置版本及config_operations回执。已应用草稿只读，重试返回原回执；历史应用不等于当前生效。每账户最多32草稿，满额需明确删除，不自动丢弃。

异步检查先模型、再检查已启用QQ的凭据获取，不激活QQ账户、不发消息、不保存访问token或响应正文。直接表单模型检查复用同一检查器与持久回执。检查期间保留配置引用并占用全局物理lease，取消/编辑/删除不得提前释放；停止时先禁止Runtime继续调度，等待连接退出，重启将孤立running/cancelling标记interrupted，不重放。schema1/2/3升级前生成原版快照，事务内补齐旧草稿列并升级4；旧制品拒绝4，正式回退恢复完整匹配备份到新目录。

## schema3日志与性格恢复（2026-10-31）

性格历史管理入口通过带当前If-Match的PUT另存版本。日志事件只存引用；输入/输出读取原消息，Native请求保存已隐藏已知凭据的消息快照。纠正、遗忘、来源过期和睡眠上下文重置会清理快照；日志分页按来源授权解析，不能由日志恢复失效上下文。30天/20,000事件上限同步清理相应快照，不删除原聊天。后台整理等任务仍使用已有审计，不伪造尚未接入的ASR/子任务/worker结果。

schema1/2升级前生成原数据库快照，事务内建立schema3与消息引用回填标记；旧制品拒绝打开schema3。正式回退恢复完整旧实例到新目录，不能仅切换代码。来源许可在认证操作、Native排队/模型请求/发布和渠道投递边界即时复核；过期后续期重置采集起点，不补采授权中断期间的消息。

## 第二批运行模块（2026-10-31）

features将channels、knowledge、automation、media、relationships与context绑定到可信宿主。管理入口沿用认证、CSRF和版本边界；QQ webhook只接受Ed25519签名原始字节，不能绕过管理API认证。QQ / iLink生产端点固定，loopback注入仅限合成测试构造器。

schema2增加来源授权、整理检查点、发送分段、作息周期、触发firing、附件、上下文选取与好感事件。schema1升级前VACUUM一致性快照，DDL和版本号在同一事务提交。数据库和主密钥须一同独立备份。启动将含糊发送标记unknown、在途模型标记interrupted，不猜测成功或自动重发。

自动整理与文字任务共享一个自动槽、每日调用预算，并计入全局两路物理网络lease。日记每批16来源保存累计JSON检查点，最多128来源、8次调用。阅读请求成功后才推进游标。审核资料不会授予发送权；触发提议先保存停用规则，再由操作者预演启用。

来源采集、模型出域、睡眠控制与唤醒控制分开。更正/遗忘后旧原文跨越水位而失去提取资格，原聊天仍可核对。撤销或过期使摘要、在途结果与依赖资料失效。睡眠原始期限持久化，先排空或取消在途再重置上下文，保留待处理输入和未发送回复，唤醒后复用。

PNG不下载任意外部URL，验证CRC、解压大小和尺寸并剥离元数据；视觉结果带ID和SHA进入Native。HTML / SVG只在认证的无脚本/网络iframe预览。Component / Python仅能登记空权限制品，没有Windows隔离证明就不编译、批准、激活或执行。
