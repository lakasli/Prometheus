# 会话记忆候选与审核

此切片让模型从明确选择的普通会话消息提出事实或偏好候选，由当前来源账户审核后保存。候选属于稳定助手身份的来源私有资料；不是用户跨渠道身份档案，不自动成为共享事实或系统指令。部署与实际测试结果见 [验收记录](memory-candidate-validation.md)。

在“助手记忆”的候选区选择一个普通会话，勾选要分析的用户消息，然后点击提取。只列出当前已认证账户拥有的来源；角色草稿测试、角色 / 记忆命令、群聊 / 频道、尚未完成的轮次以及遗忘水位以前的消息不能用于提取。明确的密钥模式和超长来源被排除，不把助手自己生成的回答当作用户确认事实。

每次最多12条、合计12000 UTF-8字节；有界扫描最近128条合格轮次，不扫描所有历史。每个会话最多一个活跃任务、全局最多20个排队 / 运行任务，最多一个提取请求。它复用既有两个原生任务槽并让普通聊天优先，20秒内至多请求模型一次，没有失败自动重试或后台自动扫描。任务排队15分钟到期，候选待审24小时到期。

提取结果最多3条，每条1000字节，并关联支持它的真实所选来源消息ID。模型必须返回严格JSON；多余字段、伪造来源、过量正文或明确秘密模式使本次任务失败。模式过滤不能识别所有敏感资料，模型也可能归纳错误，因此页面显示正文和来源供审核，不把模型自报概率当作准确率。

“接受”会先展示具体正文、来源和私有范围；确认后同一事务创建一条来源私有记忆并记录候选 / 记忆关系及审核审计。不能在请求中指定另一个owner或直接发布shared，也不覆盖已经确认的其他记忆；共享仍通过记忆库原有明确发布流程。重复提交旧版本返回冲突，不新增重复记忆。审核通过的记忆仍属于明确确认的`explicit`记录，提取与审核来源另保存在候选元数据中。

“拒绝”、到期、来源变更、遗忘和接受均清除候选正文，保留不含正文的状态与来源引用。接受后仅保留关联memory ID，记忆的纠正和遗忘继续使用原有入口。原始聊天与离线备份按独立策略保留，不把候选正文清除称为全部源资料已擦除。

来源固定真实owner、消息ID与摘要、独立epoch及记忆history floor。纠正 / 遗忘在同一事务推进候选epoch并阻止迟到模型结果落库；同一floor发生第二次修改也使旧审核失效。模型HTTP尚未退出时保留占用lease，取消不能绕过单提取或配置并发上限。重启将未完成请求记为interrupted，不重发；未开始的有效排队任务按来源重新验证。

接口全部位于受认证、Origin / CSRF保护的`/api/admin/v1`：

| 接口 | 行为 |
| --- | --- |
| `GET /conversations/{id}/memory-candidates` | 读取候选和可选来源，返回opaque `source_revision` / ETag |
| `POST /conversations/{id}/memory-candidates/extract` | 显式`source_message_ids`和来源If-Match；返回202任务 |
| `GET /memory-candidate-jobs/{id}`、`DELETE` | 当前owner查询或按job版本取消 |
| `GET /memory-candidates/{id}` | 当前owner查询单条候选 |
| `POST /memory-candidates/{id}/accept`、`/reject` | 空对象body和候选If-Match，事务审核 |

空表初始化不抬高全局reader要求；实际任务或候选失效语义使用后保持reader5，并要求`memory_candidates`发布能力。清空正文不允许旧版本忽略审核或遗忘状态。私有凭据引用只在受保护的冻结job配置中使用，不返回管理DTO或模型源资料；活跃job引用的密钥不能删除。
