# 单一助手性格与运行日志

2026-10-26 用户确认：每个实例只有一个助手性格。角色设计并入“助手与模型”，对话工作台改为“日志记录”，删除“任务与诊断”页。该决定取代旧多角色切换及开发诊断页面的组织要求，历史验收记录保持不变。

## 性格

`GET /api/admin/v1/assistant/personality` 返回当前性格、revision 与 etag。`PUT` 提交 `{personality:{name,description,personality,scenario,system_prompt,mes_example}}`，须带 `If-Match` 和管理会话 CSRF；过期版本拒绝覆盖。字段沿用现有文本编译与长度校验，不授予工具或媒体权限。

`GET /api/admin/v1/assistant/personality/history` 提供最近 20 个历史版本。页面恢复历史字段时仍通过带当前 `If-Match` 的 `PUT` 保存成新版本；只恢复性格，不回滚模型配置或历史 Run。旧助手配置的 32,000 字节系统提示在首次未保存状态下按原文运行，编辑保存时执行新字段与总长度校验，不静默截断。

首次读取沿用原实例默认已发布卡的文本；没有默认卡时使用助手配置。编辑保存后对后续入队的 Run 生效，Web / CLI / QQ / 微信及触发任务使用同一性格；已入队任务继续其冻结版本。旧卡、会话和完成记录不删除，旧角色选择 / 写接口停用，CLI 不再接受角色选择参数。长期记忆继续属于稳定 assistant identity，并沿用 shared / private 的来源域。

## 日志

`GET /api/admin/v1/runtime-logs` 提供只读持久事件，支持 `limit`、`cursor`、`kind`、`status`、`run_id`、`q`。返回事件时间、类别、状态、来源、Run / 会话引用、内容与结构化详情，按自增 ID 逆序分页。刷新从最新一页开始，加载更多沿当前筛选继续。

事件覆盖已接入的模型输入 / 输出与上下文、Run 状态、工具与插件工作、视觉处理、Piper 语音合成、渠道投递和管理 / 记忆等状态。ASR 和 subagent 尚未接入，不产生模拟成功记录。日志不提供执行命令、发送消息、调用工具或切换性格的入口。

仅认证管理员可读，Web 私有数据按 owner 隔离，渠道运行记录使用明确的来源标签。响应禁止缓存；凭证、认证头、秘密文件和完整配置不复制到日志。模型上下文引用现有可失效快照，避免遗忘后从日志副本恢复被清除的内容。事件保留 30 天且最多 20,000 条，原始会话 / Run / 用户数据继续遵循各自策略；不会因事件到期删除历史消息。

发布、测试、实际覆盖与未执行项见 [本轮验收记录](assistant-runtime-logs-validation.md)。
