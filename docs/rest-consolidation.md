# 睡眠整理执行契约

本文件说明 `rest_consolidation` 的实际实现边界。它是睡眠协调器的低优先级执行器，不代表睡眠、人物自动推断或主动联系已全部交付。计划睡眠、自然控制及来源出域仍默认关闭。运行接入、正式 SHA、远端模型与渠道验收由本轮交付记录分别确认。

## 冻结批次和同周期派生

接受睡眠时冻结来源策略版本、owner、事件 / 日记 / 人物 rowid 截止、删除 epoch，以及当时实际模型配置 revision、配置摘要、provider、model 和 credential 引用。新增表不保存密钥、人格正文或另一份来源正文。当前活动模型 profile 改变后，本周期拒绝新模型发送和结果提交，不静默换 provider。

`rest_cycle_refs` 记录初始来源。日记写入后，宿主在同一事务内完成 canonical 写入、`finish_job_in` 和 `register_produced_entry_in`，生成 `rest_produced_refs`。该证明绑定 cycle、owner、日记 ID / revision / digest、真实作业 / attempt / fence、完整父引用摘要和 DAG 阶段。阶段一只能来自本周期事件，阶段二只能来自有效日父本；模型和管理 API 没有签发证明的入口。消费者逐层验证原始来源或较早的有效派生来源，拒绝自引、跨 owner、旧版本、撤权和删除。不会扫描任意最新记录来补齐旧批次。

本扩展在 Rest 首次正式发布前加入，Rest reader 标识仍为 1。初始化同时建立派生证明与执行器元数据表；缺失表 / 不兼容字段产生错误，不把部分 schema 当作授权。已发布日记继续要求 reader2，不能降级到 reader1。

## 实际模型和写入

每次请求只读取同 owner、同 visibility、同来源 conversation 的最多 16 个精确引用。未知来源、多个私聊会话混合、敏感内容、单批正文超过 20,000 字节、序列化请求超过 22,000 字节，或没有有界完整行时明确阻断。当前不将超过 16 个来源的同一日或周月期切成多个模型批次；该期保留 `partial` / `source_batch_limit`，不截取前 16 条声称覆盖。其他有界期仍可继续。

模型只返回来源 ID 与原文整行选择，宿主检查闭集 JSON、完整输出、每项来源恰好一次、原文完整行相等和摘录摘要。任意自由总结、置信度、自造来源、截取否定句片段、未闭合或截断输出均拒绝。正文由宿主生成，保留“来源陈述 / 计划或约定 / 取消 / 未知”“未经独立核验”“不证明已完成或已送达”标签。当前是可核验原文选取，不声称完成一般语义理解或生成自然度验收。

claim、正文读取、同事务写入分别重验来源；发送前与请求期间持续复验 cycle、profile 和撤权。canonical 写入采用预期 revision 比较，人工修订、已删除目标、截止后新事件、不同来源会话及原始来源覆盖冲突均拒绝覆盖。日 / 周 / 月沿用现有日记、版本、normalized sources、parents 和全文索引，不另建永久事实库。稀疏父日记、观测缺口和当前日草稿保留不完整状态，不提升为全覆盖；普通派生更版不推进旧历史 floor。

周 / 月只处理已经结束的自然期，并可消费同 cycle 刚成功产生的日父本。月份仅聚合当月日记，不叠加周记。当前有界来源超限仍报告部分完成。人物候选与好感写入没有独立睡眠授权接口，相关步骤对有资料周期明确记录 `independent_permission_unavailable` 和零写入；日记出域许可不代替人物推断、批准或好感修改许可。

## 接入与物理生命周期

宿主优先调用 `claim_next(&AppState)`，得到私有字段的 `ClaimedJob`，再交给 `run_claimed`。`prepare_next_in(db, clock)` 是事务内底层入口，返回后宿主必须继续持有该 durable attempt，不能自行清 lease 或重建新 claim。`claim_next` 的 guard 在 future 首次轮询前已经存在，未轮询便丢弃会记录本 attempt 的 unknown 并结束其无实际 transport 的占用。

实际 HTTP 复用普通模型客户端、凭证引用和网络边界，最长 40 秒；作业和周期预算在开始前原子预留，不因失败返还。自动槽由 RestStore 真实物理工作统计和宿主统一调度控制。`credential_in_use` 应接入凭证删除门禁。不能仅统计逻辑 running 状态。

显式唤醒、截止、撤权和取消使逻辑结果失效，但不提前释放网络占用。请求 future 真实结束或销毁后才调用 `request_ended_in`。其他 native / model lease、已领取 Outbox 和 unknown 事实保持不变；unknown 不自动重试。重启恢复仅在宿主持有独占目录锁、确认原进程退出后调用 RestStore 恢复接口。唤醒在时钟 / 磁盘模型门禁之前推进，新整理请求仍受这些门禁限制。

索引步骤检查本周期实际派生日记的来源证明及 SQLite FTS 内容，检查点只存引用计数和摘要。有来源失效、缺权限或阶段冲突时保留明确部分完成并按原计划唤醒；零来源周期记录零资料，不调用模型，不写空经历。

## 验证边界

专测使用临时 AppState、合成来源和真实 loopback HTTP，不读写正式实例。覆盖日→周/月同周期派生链、不同 owner / 会话、截断与捏造、原文否定、敏感内容、晚到消息、人工修订、撤权、profile 切换、unknown 实际投递投影、真实遗忘流程、重启恢复、未轮询 future、唤醒期间 lease 保持及部分覆盖。它们不等同于远端真实模型、真实渠道或最终运行集成通过；最终命令、SHA 与结果须另记。
