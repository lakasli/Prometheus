# 日记系统实现契约

日记属于稳定的 `assistant.identity.v1`。日期按来源授权的 IANA 时区划分，默认 `Asia/Shanghai`；同一个来源 owner 分别生成日记、周记与月记，私人来源不混写成公开日记。管理页提供「日记与资料」，运行日志仍是独立只读页面。

## 来源与生成

事件记录真实发生时间、观察 / 导入时间、原始类型和 ID、revision、来源 owner、会话 / 消息引用、可见范围和陈述类别。显式记录立即入库。默认不自动采集聊天，也不将资料发送到模型；管理员分别启用来源采集和模型整理授权。授权只影响对应来源，不把一个管理登录身份当作所有渠道人物的身份。

自动采集限已完成的 `model / skill_text` 真实会话。草稿性格测试、控制命令、自动任务、自发发送和疑似凭证内容不进入长期事件。历史记录不因启用策略自动回填到授权开始之前。新渠道来源须在管理页选择真实来源后授权，不需要手工填写内部 owner ID。

单一持久调度循环在可信时钟下于当地 00:05 后封存前日；每批最多扫描 64 个完成 Run、处理 16 个来源和每来源 4 个有来源的日期。按持久日期检查点补记，无逐人定时器或常驻进程。默认建立单一性格自身的私有日期分区，零互动日也会形成记录，不因此授权采集聊天。周记为周一至周日，月记为自然月；各自引用该周期内最多 7 / 31 份已封存日记的固定版本，并保留全部原始事件来源，月记不叠加跨月周记。为避免首周早于首次互动而永远缺父，无事件的已结束日期可生成明确标记未观测的空父日记；有事件的缺失日仍从有界日期检查点处理。每个周期 / 来源采用确定性 ID，重复整理在来源指纹不变时不增加版本。

初始版本是明确标示的 `evidence_excerpt_v1` 证据摘录，感受留空。来源允许模型出域后，日记模型任务以独立来源 envelope 在普通对话之外调用同一个 provider 客户端；生成事实与主观感受分栏，使用 `model:<模型名>` 标识。没有互动时不调用模型编造经历；缺少运行观测的日期明确显示未观测，无互动且观察完整时记录「今日无新互动 / 无新经历」。模型超时或失败保留摘录、错误和重试状态。

模型整理与自主阅读 / 人物整理共用自动后台单槽，同时计入现有总请求准入，排在交互消息之后。每批连续失败最多 3 次，失败至少冷却 60 秒；日记每来源滚动 24 小时最多 8 次请求、全局最多 24 次。单日仍最多 200 条原始来源；周 / 月不再受 200 条总数限制，而以父日记分批归并。每次父 / fragment payload 预留系统开销，发送前再次校验完整 provider JSON 不超过 48,000 字节，输出上限 2,400 token，超时 45 秒。

周 / 月的确定性初版 `parent_catalogue_v2` 是全量来源目录，明确说明尚未完成模型整理。原始来源关系通过 SQL 全量登记，模型读取固定父版本；过长父集合分为多个 fragment，逐批保存覆盖区间、输入摘要和输出，再递归归并前一层所有 fragment。只有某层全部单元被一次最终归并覆盖后，才替换为 `model:<模型名>` 正文。fragment 成功重置本批失败次数，失败、每日预算等待和服务重启均保留既有成功 fragment，不能从首批无限重做。来源授权或原始事件改变会拒绝旧结果，父日记单纯由完整摘录 r1 丰富为模型 r2 不使已选 r1 失效，也不会无限重生成周 / 月记。

`diary_entry_version_coverage` 记录每个版本的真实来源覆盖；日记摘录超过 12 KB 会显示截断说明并标记覆盖不完整，不把它作为完成的父内容。缺父或父内容未完整时，聚合任务等待且不占模型槽，选择器继续检查其他已就绪任务。真正超出日容量、输入容量或每日预算时保持明确阻断 / 等待；管理员可用 `retry_failed:true` 显式恢复失败批次，周期调度不会偷偷清空失败次数。当前没有开放 Python 执行动作或新的任意工具权限。

## 修订、遗忘与撤权

修改和遗忘须携带 `If-Match`。事件更正产生新 revision，旧事件版本正文清除，引用它的日 / 周 / 月记立即变为不可检索的 `invalidated`，旧派生版本正文、所有层次模型 fragment 及归并检查点同步清除。该级联按完整原始来源链执行，310 条月来源中任一条被遗忘都会使对应月记失效，而不是只覆盖首 200 条。人物字段、关系边和好感派生来源经同一事务级联失效。已进入上下文的资料通过来源域水位撤回后续使用，旧摘要、记忆候选、视觉描述、未发送 QQ / 微信队列及 prompt snapshot 失效；实际在途请求 lease 保持到 HTTP future 结束。

遗忘保留事件 ID 与 tombstone，不删除或重建用户数据库，不使重启、迟到采集或重新导入复活同一 origin。来源撤权保留最大事件 rowid 水位；重新启用仅允许新授权事件，旧事件不因重新授权自动恢复。原始渠道消息与离线备份有独立保留期，日记遗忘不会虚称已删除这些副本。备份恢复须先重放 tombstone 和来源撤权水位，再恢复调度。

模型提交同时核对条目 revision、来源事件 revision / 指纹、删除 epoch、来源授权版本；任一变化拒收旧结果。管理查询可以审计全部授权数据，普通对话检索仅取 `shared` 与当前可信 owner 的 `private` 数据。事件与条目采用 FTS5 trigram 检索，三字符以上在 MATCH 中同时约束稳定身份与来源 owner / shared；一至二字符使用 SQL 子串搜索，所有路径均在 SQL scope 过滤后分页。开启 FTS5 secure-delete，更正、遗忘、撤权同步移除旧索引。模型不能指定另一个 owner 获取资料；普通长中文输入按 UTF-8 字节边界裁切检索词，避免超过检索接口预算导致整个回复失败。尚未据此宣称 10 万段检索性能指标已达标。

## 旧记忆兼容迁移

升级初始化将历史 `memory_records` 映射为 `legacy:<旧ID>` 的 `legacy_memory` 事件，保留原 ID、owner、visibility、revision、时间和 tombstone。历史导入的观察时间标为本次迁移时间，不冒充新发生的对话。

现有 `/memory` 命令与 API 在过渡期保留旧 ID / 版本语义；日记事件界面对 legacy 记录的更正 / 遗忘也调用同一旧接口事务。旧表是兼容投影，SQLite 触发器在同一事务同步 canonical event；更正和遗忘先走统一的日记派生失效。这是兼容过渡实现，尚未删除旧表，也未把旧查询全面迁移为单一 canonical 读取。切换门禁是：旧命令 / 候选审核全部经日记事务、来源 / 删除链恢复演练通过后，再将旧表转只读投影。部署 capability gate 阻止不能识别日记数据的旧制品直接降级；数据回滚必须单独评估迁移与 tombstone，不能仅切旧提交。

本次层次整理使用 `diary_meta.schema_version=2`，事务支持从 reader 1 迁移，未知未来版本拒绝启动。新增父覆盖、版本覆盖、模型归并与 fragment 表；旧 reader 1 不知道如何删除 fragment 中的私有派生正文，因此不允许直接降级到旧制品。`diary_model_leases.input_bytes` 保存实际发送 JSON 的字节数，不保存 prompt 正文。

普通对话先检索当前 owner 的 private 与可见 shared 条目；没有字面命中时，最多补入四份最近可见日记，以 `recent_visible_day` 明确标记为近期资料而非命中。事实与感受按 UTF-8 边界摘录，并标注截断，完整序列化 JSON 总量不超过 8,000 字节，不重复附带合并正文。只有实际送入上下文的条目登记引用；删除或撤权沿同一失效链清除后续历史快照，隔离测试不使用该回退。

## 管理 API

所有路径均以 `/api/admin/v1/diary` 为前缀，使用现有管理员认证、Origin 与 CSRF 中间件。

| 路径 | 方法 / 作用 |
| --- | --- |
| `/sources` | GET；列举真实来源、展示名称和当前授权状态 |
| `/policies` | GET / PUT；版本化采集与模型出域授权，首次 `If-Match: 0` |
| `/events` | GET / POST；搜索事件、显式记录 |
| `/events/{id}` | GET / PATCH / DELETE；查看、更正、遗忘；后两者须 `If-Match` |
| `/entries` | GET；按周期 / 日期 / 来源 / 可见范围 / 关键词筛选 |
| `/entries/{id}` | GET；查看日记事实、感受、来源覆盖和生成方式 |
| `/entries/{id}/sources` | GET；来源事件及真实 revision，`limit` 默认 100、最多 200，`offset` 分页；返回 `items/total/limit/offset/has_more` |
| `/consolidate` | POST；受控整理指定来源和周期，私人来源省略 owner 时绑定当前管理员 |
| `/export` | GET；重新检查有效来源，分别最多导出 100 条事件 / 日记，并返回分页信息 |
| `/status` | GET；检查点、删除水位及模型任务状态 |

周期范围使用左闭右开区间。`/consolidate` 的 JSON 为 `{period,day,timezone,visibility,source_owner_id,retry_failed?:false}`，`period` 取 `day / week / month`。`retry_failed:true` 只在手动管理调用中恢复当前来源 / 版本仍有效的失败任务，保留成功 fragment，仍受每日配额限制；已完成模型条目不因此再次生成。日记创建 / 变更响应包含 `ETag`。未知字段、未来经历、无明确发布确认的 shared 事件和疑似凭证内容被拒绝。模型协议使用固定 `DSH_DIARY_GENERATOR_V2` 标记，不硬编码性格姓名。

## 验证与未交付范围

`cargo test -p dshd diary --lib` 覆盖来源隔离、修订冲突、跨期失效、tombstone 重启、无互动 / 未观测日、周 / 月边界去重、旧 ID 迁移、来源授权 / 模型出域、陈旧模型结果、FTS 删除安全、长中文检索及控制 / 草稿过滤。`cargo test -p dshd systems_integration --lib` 以已填充三后台队列和真实挂起 HTTP 验证单一自动槽、交互优先、取消 / 来源失效后的 lease 释放，以及 claim 在首次 poll 前丢弃时不泄露占用。`python tools/diary-smoke.py --binary <制品> --web-dir <静态目录> --report <结果.json>` 在临时实例验证真实进程 / 认证 API / mock provider；加入 `--live-config-from <获授权生产data目录>` 可使用当前外部模型配置，仅向其发送合成日记，不复制生产日记或渠道数据。实际部署 SHA 与执行结果写独立验收记录。

`python tools/diary-hierarchy-smoke.py --binary <制品> --web-dir <静态目录> --report <结果.json>` 单独验收 31 天、310 个合成事件：先禁用模型并封存所有完整日记，再仅为月记授权模型，父正文总量超过 48 KB，至少两个持久 fragment 后再最终归并；验证调用数不超过 8、每请求字节数不超过 48,000、所有 310 条来源可分页取回，删除其中一源后日 / 周 / 月及 fragment 正文同步失效、重启不复活。该脚本也支持 `--live-config-from`；mock 与真实外部模型结果分别记录，不互相替代。单元回归另外覆盖中途重启从 fragment 水位继续、失败须手动恢复，以及等待每日预算不消耗失败次数并在额度窗口恢复后继续。

本模块没有声称已实现完整睡眠状态机、好友软件观察接入、任意媒体内容自动整理、向量检索、开放 Python 动作或主动渠道发送。现有来源权限不足时不采集；模型 / 预算不足时保留明确状态，不将摘录或计划展示称为实际模型生成完成。
