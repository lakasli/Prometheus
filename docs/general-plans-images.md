# 自然安排与常用图片

2026-10-27 用户取消抄诗专用配置与固定爱好。本契约替代 [前轮小安排契约](daily-life-rhythm.md) 中的四首诗目录、专门开关及固定句式补录；原有验收记录仍代表当时版本。

## 自主安排

日程页只保留每日作息和现有工作目标 / 自主授权，不新增爱好配置。07:00 起床、23:00 睡觉、提前一分钟选择、睡眠上下文边界和日记记忆沿用原契约。性格资产更新为 [v3](examples/liu-jiahui-personality-v3.json)，没有抄诗偏好或示范；升级不覆盖已保存性格，正式实例另经认证版本化保存。

聊天时使用现有 `schedule_autonomy_grants` 中有效的写作授权，按来源、有效期、版本、窗口、预算和忙闲提供最多三个十分钟时段。模型自然决定是否安排，当前可执行能力是保存文字成果；没有物理行动、外发或任意脚本执行能力。新 `self_activity` 仅允许宿主时段 ID、标题和完整正文，最多 80 字标题、3000 字 / 12000 字节正文。正文不作为代码、路径或 URL 执行。

回复与安排在同一最终事务保存，重复 Run 幂等，提交前重验授权和冲突。有新意图但漏填结构时，在已缓存原回复之后，使用同一前台请求租约顺序进行至多一次语义核对（20 秒、4096 输出 token 上限），只传本轮生成回复、可用时段和能力，不扩大历史来源。引用、过去、条件、建议、一般愿望及只是答应以后登记不建活动。无法落实的新承诺或核对失败阻止发布。结果按原回复摘要缓存；取消、来源失效和删除仍受既有清理及提交栅栏约束，中断后不自动重复这次核对。

有可用时段时，末尾呈现指令明确替换最外层数组，要求只返回一个 `{reply,self_activity}` 对象，无安排时为 null。兼容模型仍先输出数组、再输出日程对象的情况，只在两个回复经严格字段解析后完全一致时合并，最终仅发布一次；差异、额外字段、重复键、解释文字或多份后续对象均拒绝。原句数、媒体、时段和授权校验继续适用。

原 QQ 漏记句式用于隔离回归，未补造历史日程或完成记录。旧诗目录只为已存在活动保留兼容读取和执行，新提示不提供目录。旧专用授权自动迁移名称为“日常自主安排”，保留所有者、限额、时间、期限并增加版本；旧兼容 API 仍可读，管理页不再调用它。

到期后保存实际文字成果、摘要、准备与保存时间，才标为完成。成果保留在原来源的日程记录中，其他来源不会取得正文。已遗忘来源的待执行草稿阻断并清除正文。获授权的日记只保存原来源私有的完成索引，不把生成正文或私人标题写入共享日记；醒后仍按来源检索。原始日志保留。睡眠边界切断旧聊天，已经合法登记的未来安排继续受自己的授权与版本约束。

## 图片接收

Web、媒体上传与 QQ 图片入口接受 PNG、JPEG/JPG、WebP、GIF、BMP，按实际字节验证而非只信扩展名或 MIME。GIF / WebP 只读取首帧，PNG 保留严格校验且拒绝 APNG。输入上限 8 MiB、12000 单边、2400 万像素，解码内存上限 128 MiB，解码共享单并发。JPEG 方向信息应用后去除元数据，规范化为单帧 PNG，最长边 2048、最多 2097152 像素、2 MiB；小图不放大。原有 CDN、重定向与来源归属限制不变。

无法打开、解码或识别时使用简短自然表达，例如“这张图我这边没打开，能再发一次给我吗？”。内部错误码和失败状态继续留在日志，失败图不会得到编造的视觉描述。模型端视觉失败的回复仍经过取消、睡眠、纠正和截止检查。管理页可显示格式与限制；普通聊天不发送技术参数清单。

## 兼容和验收边界

发布能力 `daily_life:2`。迁移后的通用授权指针、新文字安排或语义核对缓存要求 reader2；门禁拒绝盲退旧版本。发布脚本在切换前做私有 SQLite 备份。旧版本回滚须遵守门禁，代码切换不等于数据恢复，不删除用户记录绕过限制。

2026-10-30 起正式目标改为 Windows，执行 [Windows 开发与部署流程](development-workflow.md)。必要检查包含相关 Rust / 前端 / Python 测试、隔离真实解码和 QQ 入站至持久 Outbox 回归、隔离进程和浏览器检查，再按固定 SHA 在 Windows 部署与测试。真实模型检查使用合成内容和有界串行请求；已知回复重放、真实语义组件、完整视觉 / Native 流程分别记账。没有真实 QQ 外发、客户端接收或视频动态理解证据时不得宣称通过。旧树莓派 SHA、命令、失败保留和结果仍见历史独立验收，不计为 Windows 通过。
