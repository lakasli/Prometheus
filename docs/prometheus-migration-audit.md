## Windows worker探针

TypeScript只可调用包内固定探针，不接受用户程序/命令；C++仅为Windows API适配及合成测试程序。探针尝试AppContainer空capabilities、精确句柄继承、干净子进程环境、原子Job Object归属、64MiB内存/20%CPU上限、单进程、子进程策略、输出上限、超时和取消。各项需实际运行证明后才有效，源码里的设置不算通过。

运行期间记录过：CreateProcess错误203（最小环境不完整）；补足Windows环境后出现4551，CodeIntegrity Operational的3077/3033记录签名级别拒绝；另一次Node启动返回UNKNOWN；后续启动子进程以3221225794（0xC0000142，DLL初始化失败）退出，没有权限探针结果。同步spawn异常现已转换为结构化blocked，避免检查器崩溃。没有关闭或绕过系统策略，也没有以改名、切换到WSL等方式开放执行功能。

命令：`npm.cmd run build:worker`、`node deploy/prometheus/verify-worker.mjs [runtime绝对目录]`，或`node apps/server/dist/cli.js worker-check --data-dir <独立检查目录>`。构建需要MSVC/Windows SDK及PowerShell7；日常纯TypeScript构建不要求原生探针。检查失败退出2，后续隔离/取消/超时/进程树场景列为未执行，绝不计为通过。打包可加`-IncludeWorkerProbe`，探针同样列入固定制品哈希。
