# 短期会话状态与来源失效契约

本页对应架构书第 5.6、7.6、9.10 节的当前实现切片。代码位于 `conversation_state.rs`、`conversation_focus.rs`、`conversation_invalidation.rs`，由普通文字请求的上下文组装接入。本文描述实现约束，不代替固定 SHA 部署、真实模型、浏览器或真实渠道验收；发布结果另记。它不代表完整自然语言理解、自然度评估、完整日程自主能力或睡眠已交付。

## 可信作用域

模型调用的 `VerifiedConversationScope` 仅由宿主根据真实 Run、会话、owner、既有身份绑定和平台发言者证据构造，不能从模型 JSON、昵称或用户自称构造。作用域包含稳定实例、完整会话、来源 owner 和当前发言者。不同私聊不合并历史；群、频道和频道私信按已记录的实际发言者分别维护短期状态，缺少或无法唯一确定发言者时不继承他人的话题或偏好。

管理读取使用独立 `management_scope_for_source_in`：核验真实管理员后恢复原来源的持久绑定和当前权限。管理身份不会替换来源 owner，不给旧 Prompt 补造新模型授权证明，也不自动授予资料读取、主动联系、日程执行或消息发送权限。

初始化状态表必须与约定表配套。聚合失效入口检查所需表和列：完全没有这两类新表时按旧数据库无状态处理；只有部分表或列缺失时拒绝操作，不把损坏状态当作空数据。

## 焦点、指代与临时表达偏好

初始策略为 **版本 1、实验性 TTL 6 小时、上限 24 小时**。每个作用域最多保留四个有效话题，以及两个有界的收尾 / 偏好控制项。TTL 是当前宿主策略参数，尚不提供独立的焦点 TTL 管理表单；这些数值不是已证明的自然度最优参数。

焦点引用真实输入，保存最多 1,024 字节的 UTF-8 完整边界摘录，不伪称语义摘要。观察在 QQ 合并批关闭、首次冻结本轮 Prompt 的事务中进行；同一 Run 重复观察只核对输入摘要，不重复写状态。状态记录受数量、正文和来源引用上限约束，旧项被替代、到期或失效时清除派生正文，不为话题创建常驻 worker。

- “继续”“接着说”及有界的“继续，先说……”等明确续接表达选择最近仍有效的话题。
- “那个方案”“它”及“按这个预算 / 参数……”等封闭指代表达存在多个有效候选时标记 `ambiguous`，只提供有来源的候选并要求必要澄清。后接的新要求不授予动作权限，也不重新建立一个只有代词的新话题。
- “换个话题：……”清除旧话题和旧话题纠正的有效投影，再以新输入建立焦点。
- “谢谢，就这样”“晚安，先不聊了”等只产生简短收尾提示，不取消订阅、不控制睡眠、不取消任务，也不修改 Linux 状态。新的实质问题可以重新打开话题。
- “这题详细点”“先别给建议”等作为当前话题的临时表达偏好；“以后简短些”等在当前会话及 TTL 内表达偏好，不自动保存为跨会话性格或长期人物字段。

匹配只覆盖明确的封闭表达。引用、假设和转发中的相同文本不能成为控制来源；未识别文本仍作为普通用户输入，不通过附加模型调用猜测控制意图。当前接入以普通文字请求为主，Skill、草稿测试和图片请求沿用各自来源与权限边界，不能据此声称所有模态都支持相同焦点操作。

跨日仅可使用仍通过来源、版本和可见水位校验的原记录。时间间隔不证明其间发生过活动。过期、未命中和遗忘分开表达：只有同作用域存在已到期话题的元数据且其来源仍有效时，续接状态才可标为 `expired`；该查询有界且不读取或恢复到期正文。已遗忘、已失效记录不能用来编造“曾有一个过期话题”。

焦点到期不等于删除仍有权读取的原始历史。普通历史是否可用仍由原消息、会话水位和其保留政策决定。

## 持续生效的纠正

短期语义纠正从既有 `turn_control` 的真实前驱关联读取，保留被纠正请求、纠正消息、话题、发布决定、来源引用和有效期。它与“抑制尚未发布的旧答案”分别记录：纠正可以用于之后的相关话题，但不能改写已经发送或结果未知的事实。

后继上下文只附带当前话题、当前纠正轮或歧义候选话题相关的有效纠正；无关新问题不会被迫携带全部旧纠正。旧摘要不能覆盖较新的明确纠正。目标不明确时要求澄清，不按相邻时间或同名自行改写另一人的记录。

纠正原文受现有识别器的有界输入限制；持久替换内容保持完整，不保存没有说明的半段替换。若完整派生对象超过 4 KiB 上限，记录 `correction_not_persisted_budget`，不保存截断对象；当轮仍由完整当前输入和已有纠正来源处理，不能宣称跨后继持久状态已保存。原请求的摘录明确作为摘录，原始输入保持不变。

该投影只修正当前交流中的理解，不自动更新人物断言、全局偏好或长期事实。长期变更继续通过已有来源、版本、审核和遗忘事务。

## 来源与敏感内容

每项状态保存 `SourceRef`，包含来源类型、ID、revision，以及需要时的 epoch / 摘要。Run 输入没有独立可变 revision，采用明确的输入版本契约和完整正文摘要；不会把自造序号说成平台 revision。历史输入不得越过当前 Run 的顺序或已生效的删除水位；当前仍在排队 / 执行的完整输入采用原有当前输入例外。

来源校验覆盖普通输入、实际投递投影、日记事件 / 条目、兼容显式记忆、已审核人物字段和已核验身份。它重新检查来源 ACL、版本、删除 / 撤权水位和必要摘要；同一人物、同名或管理员审计权都不能扩大模型的来源范围。

短期状态复用会话摘要的 `contains_sensitive` 格式检查，包含明显密钥、令牌、私钥和密码赋值等；命中时不把输入或其纠正前驱复制为新派生正文。该检查不声称识别所有敏感自然语言事实。原始消息、历史备份和已经交给模型的内容有独立保留与处理边界，清除短期投影不等于全部介质已物理删除。

## 实际使用、TTL 与失效

上下文预算选择前可读取候选；只为最终放入 Prompt 的焦点、纠正、约定、人物、记忆和日记登记使用关系。人物候选入口不提前写 `relationship_context_uses`；选中后在同一事务重新核对结果并登记。预算与状态快照保存引用、版本、字节 / token 估计和原因，不再复制一份派生正文。

已冻结的短期状态快照不可重写。请求提交、呈现 / 媒体准备及结果发布前，宿主重新核对实际使用的实体仍存在、revision 一致、未失效、正文有效且尚未到期。排队或模型请求跨越 TTL 时拒绝继续使用该证明；这不会提前释放在途 HTTP / 子进程占用的物理 lease。

来源更正、遗忘、撤权及身份变化接入以下失效链：

| 入口 | 新状态处理 |
| --- | --- |
| 显式记忆更正 / 遗忘 | 按旧记忆 revision 失效精确引用；原流程决定的会话水位范围同时清除短期视图。 |
| 日记事件更正 / 遗忘、来源撤权 | 按真实事件 / 条目 revision 清除相关视图，保留删除水位。 |
| 日 / 周 / 月条目正常换版或模型归并 | 只失效实际引用旧条目版本的新状态消费者；不因此新增历史水位推进。 |
| 人物字段替代 / 遗忘、来源失效 | 按实际字段 ID / revision 失效相关状态；身份映射变化按真实会话清除短期视图。 |
| 旧记忆 / 日记 / 人物流程已选择失效的会话 | 沿原 scope 清除新投影，保持原历史水位规则。 |

聚合失效先由规范化来源与使用关系确定精确消费者，不按“同一秒更新过”扫描其他来源。只有实际使用受影响新状态的 queued / running Run 被逻辑取消；未领取的 QQ 句段 / Outbox 与微信待发送项停止。sending、sent、accepted、unknown 的尝试、回执及实际副作用保留；不自动重发、不声称撤回。物理 lease 由原请求所有者结束或销毁传输后释放，失效代码不删除这些 lease。

精确来源换版只推进相关实体 revision 和状态，不提升整个短期作用域 epoch；同会话中没有使用该来源的独立冻结上下文继续有效。明确作用域失效才提升对应 epoch，既有历史删除水位仍由原领域流程决定。

遗忘清除派生正文和受影响 Prompt 副本，保留脱敏引用、状态与删除水位。重启、重复观察或重新授权不得据旧引用复活被清除内容。独立日程的执行授权与取消仍由日程服务处理，删除短期约定不伪造日程已撤销。

## 验证边界

领域回归覆盖私聊 A / B、群内不同发言者、未知发言者、话题数量上限、指代歧义、收尾与新问题、完整纠正、跨日与 TTL、输入幂等、来源遗忘、管理与模型作用域分离、部分投递 / unknown、lease 保留，以及真实应用存储中的记忆、日记和人物变更入口。

可使用 `cargo test -p dshd conversation_focus --lib --offline`、`cargo test -p dshd conversation_invalidation --lib --offline` 及相关关系 / 日记回归检查。真实进程回放、外部模型自然表现、浏览器和渠道结果必须分别记录；协议测试、少量算式或模型自评不等于架构要求的 40 场景、人工对照或自然度达标。

本切片不默认启用主动外发或睡眠。日程已建立、模型声称答应、约定被确认、实际执行、平台接受和用户已读继续分别判断，不授予新的模型工具权限。
