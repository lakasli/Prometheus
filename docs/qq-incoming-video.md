# QQ 私聊视频接收与原样回发

本切片补齐 QQ owner 的视频制品入口，使普通聊天的 `type=video` 能引用该用户刚上传的视频。实现不包含视频帧理解、视频生成、音轨识别或 ASR；模型只获得用户文字说明、受控附件说明和当前会话允许引用的制品 ID，不获得视频字节或 QQ 下载地址。实际部署 SHA、真实平台接收和客户端播放以独立验收记录为准。

## 接收与授权

仅接收 `C2C_MESSAGE_CREATE` 中的单个附件。支持一张 PNG 图片或一个标准 MP4 视频；多附件、群/频道媒体、音频输入、未支持格式和带控制命令的媒体消息保持不可用，不将附件 caption 当作 `/记住` 或角色控制命令执行。PNG 图片理解维持既有 1MiB 限额与 Vision 路径，视频接收不依赖 Vision 配置。

认证 Gateway / 签名 Webhook 先持久化有界接收记录，再由一个消费者下载。回复 deadline 在收到事件时冻结，下载不延长被动回复窗口。下载只接受既有 QQ CDN 白名单的 HTTPS 引用；拒绝重定向、凭据、私网或混合 DNS 结果，连接固定到已检查的公共 DNS 地址。DNS 最多 3 秒，HTTP 整体最多 12 秒，外层处理最多 20 秒；响应声明长度和实际流式字节数都受限。签名下载引用仅暂存在私有接收记录中，处理结束即清除，不进入模型提示、会话正文或普通日志。

视频最大 20MiB、最长 60 秒，最多一条 H.264 视频轨道和受限音频轨道。仅接受自包含、非分片 MP4：校验顶层 box 边界、品牌、电影与轨道时长、H.264 配置、容器尺寸、样本大小/时间表、块映射与 `mdat` 范围，拒绝外部 data reference、重叠或越界样本及未知轨道类型。容器尺寸最多 4096×4096，像素积最多 8,294,400。音轨可随原文件保存与回发，但不解码或识别。此校验不等于逐帧解码，也不承诺任意编码文件可在所有客户端播放。

## 普通对话与制品

校验成功后，Inbox、用户消息、Run、当前 QQ owner/会话的 private 视频制品和接收完成状态在同一事务中保存。任一存储步骤失败均回滚，不留下可单独引用的制品；重放相同事件或消息 ID 不重复生成 Run 或制品。制品沿用会话 owner、上下文遗忘水位、24 小时 TTL 和既有总量配额，不跨用户或会话列出。

这类制品是用户原始附件，`source_run_id=NULL`；它不属于模型派生结果。遗忘水位变化后，既有媒体读取与维护清理立即阻断旧制品引用。普通模型回复仍遵守逐句 JSON 列表、数量限额、出站间隔、持久化顺序和不确定发送不盲目重试的规则。请求回传视频时，模型必须返回 `type=video` 与当前白名单的 `asset_id`；普通文字中的“已发回”不会触发文件发送。

## 本地回归与真实联调边界

新增 Rust 回归使用 `crates/dshd/testdata/synthetic-h264.mp4`：该 11,508 字节、2 秒、320×240 的合成 H.264 文件来自本项目已有合成联调素材，无用户影像。覆盖实际容器、畸形/外部引用/越界/超时长拒绝、非群/单附件/控制命令/大小/CDN 边界，以及同一私有 Inbox → Native caption 请求 → `type=video` Outbox 的闭环、幂等与遗忘失效。

Native 回归使用本地模拟文本模型，证明提示和持久化协议，不代表真实 QQ 网络上传或客户端播放通过。真实联调仍需从 QQ 客户端上传视频、发出原样回传请求，并分别核对平台回执、客户端视频条目与实际播放。

参考：[QQ 富媒体说明](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/rich-media.html)、[Apple 文件格式说明](https://developer.apple.com/documentation/quicktime-file-format)。本项目只实现受限容器解析，不引入 FFmpeg 解码或新常驻媒体服务。
