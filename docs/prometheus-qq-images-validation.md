## 实际范围

QQ 签名 Webhook 和既有 WebSocket 共同进入持久接收入口。当前仅接收 C2C 每条一张 PNG/JPEG/GIF/WebP/BMP 图片，沿用[常用图片](prometheus-common-images-validation.md)的 8MiB、24MP 和规范化限制。先下载、实际解码，再由 Vision 描述和 Native 回复；附件文字不执行记忆或 Skill 控制命令。未配置、格式不支持、过大、附件过多或下载失败时，由宿主如实说明，不能声称看过画面。专项测试直接覆盖签名 Webhook；WebSocket 的既有连接/接收回归通过，不冒称本批已做真实网关附件联调。

仅允许旧实现的精确 HTTPS CDN 主机族。真实 socket 的 DNS 查询拒绝私网和公私混合结果，不按预检查后重新解析；不跟随重定向，不附加平台凭据、Cookie 或模型凭据。下载限制 8MiB，拒绝压缩响应、错误 MIME、长度越界、空正文和不完整流；空闲超时 3 秒，整体处理截止 20 秒。测试用 loopback 地址只由进程内合成夹具注入，生产 CLI 和管理配置不能开启此例外。私有 URL 加密保存，只在未完成接收期间保留，不写入审计正文或管理页。

平台消息 ID 和传输事件 ID 分开去重；不同网关事件 ID 重投同一消息、退出重启后重投仍只有一个接收/Run。先检查重复，再检查队列容量；超额新事件返回 503，不提前确认。普通接收最多 1000 项、加密载荷 32MiB，待处理附件最多 200 项；下载/解码一次一个，配额不足保留原期限等待。媒体前后的文字保持顺序，不跨附件合并。Run 幂等键使用事件键摘要，合法长消息和 256 字节平台 ID 不因内部标识限制失效。

附件、Run、用户消息、来源映射及规范图片归档在同一事务提交，提交后才启动模型。存储错误回滚全部新对象，保留接收记录重试。配置、模型策略、来源水位或单会话上下文失效时撤销实际下载，完成物理 socket 关闭后才解除占用；解码也等待实际处理结束。凭据仍被在途接收引用时不得删除。正常退出中断下载并保留原截止时间，重新启动可续接尚未提交的事件；已经调用模型的失败或中断遵循既有 Run 规则，不自动重放为另一份回答。

识图输入在完成、失败、取消和退出后清除。另保存的**规范化来源图片不是原始附件字节**：24 小时到期、每来源最多 32 份/64MiB、全实例 128MiB，遗忘水位清除；不提供模型任意 URL、文件路径或收件人能力，也尚未提供渠道图片外发。失败 Run 保留失败状态，没有伪造的 assistant 消息；有界失败说明与实际投递单独记录。新的认证接收记录页仅展示状态、错误码和关联 Run 状态，实际发送仍查看独立投递记录。

新增递归来源检查：记录通过 `derivations` 引用被排除的附件或未核实回复时，其后续派生记录也不能进入 Native 记忆或整理请求；循环引用会终止。已有记录正文仍可查看，不通过删除历史绕过迁移。新的识图对话、失败说明与图像派生回答继续遵循来源候选、摘要和日记的独立边界。
